# 冰蓝桌面 MVP 产品设计

> 文档状态：产品基线（可用于拆解开发任务）  
> 版本：0.8
> 更新日期：2026-10-03
> 适用平台：Windows 11 x64；Windows 10 2004 及以上尽力支持（不含任务栏外观）

## 1. 一句话定义

冰蓝桌面是一款轻量的 Windows 11 桌面伴侣：用一个应用统一提供桌面组件、待办、普通便签、桌面分组盒、应用 Dock、任务栏外观和主题导入导出，让普通用户在 5 分钟内获得一套完整、协调、可恢复的桌面。

它不是通用皮肤引擎，也不替换 Windows Shell。

## 2. 背景与机会

当前桌面效果依赖多款彼此独立的组件、Dock、文件收纳和任务栏透明工具，也带来明显成本：

- 四个安装包、四个常驻程序、四个开机启动项和分散的设置入口。
- 主题由皮肤、坐标、路径、城市和快捷方式拼成，难以完整分享。
- 不同程序的 DPI、窗口层级、拖动和全屏规则不一致，容易互相影响。
- 朋友想复刻效果时，需要学习多个工具并手工修正大量本机路径。
- 某个模块出错时，很难判断是皮肤、宿主、系统缩放还是第三方软件的问题。

产品机会不是把四个软件原样塞进一个壳，而是抽取实际使用的少量能力，做成一个有统一视觉、统一状态和明确安全边界的产品。

## 3. 产品目标

### 3.1 核心目标

1. 一次安装、一个常驻进程、一个开机启动项、一个托盘入口和一个设置中心。
2. 首次安装后 5 分钟内完成主题选择、姓名和城市设置、常用应用绑定并看到完整桌面。
3. 覆盖当前实际使用的核心功能，不要求兼容第三方皮肤或 Dock 配置。
4. 主题可导出和分享，但不会携带待办、文件路径、姓名、城市等私人数据。
5. 出错、退出或卸载后不破坏 Explorer、原文件和 Windows 原生任务栏。

### 3.2 MVP 成功标准

- 新用户只使用一个安装包即可复现默认冰蓝主题。
- 应用只注册一个开机启动入口；各模块不能生成自己的启动项。
- 默认主题包含桌面信息、待办、文件收纳、Dock 和可选任务栏透明效果。
- 主题在 100%、125%、150% 缩放和多显示器环境下不会跑出可用区域。
- 文件收纳默认只保存映射，移除映射不会删除或移动原文件。
- 应用退出和异常恢复后，Windows 任务栏状态可以恢复。
- 稳态内存、空闲 CPU 和启动耗时达到第 13 节中的阶段性预算。

## 4. 目标用户与核心任务

### 4.1 首要用户

希望桌面干净、统一、好看，但不愿学习多个美化工具的 Windows 11 用户。他们会使用基本设置，却不应被要求编辑 INI、注册表或脚本。

### 4.2 核心任务

- 快速看时间、天气和电脑运行状态。
- 记录、编辑、完成和删除当天待办，并用独立普通便签保存多行自由文本。
- 把应用快捷方式、桌面入口、常用文件和文件夹组合成视觉分组，但保留文件原本位置。
- 从统一 Dock 启动应用、切换窗口和查看运行状态。
- 让任务栏与主题协调，同时保留 Windows 开始菜单、通知和托盘。
- 将完整视觉方案分享给朋友，而不泄露私人内容或绝对路径。

## 5. 产品原则

1. **少而完整**：只实现真实使用的能力，不做兼容所有皮肤的框架。
2. **Windows 仍是主人**：保留 Explorer、开始菜单、通知区域、Alt+Tab 和虚拟桌面。
3. **默认安全**：文件收纳不移动原文件；任务栏改动可恢复；核心功能不要求管理员权限。
4. **统一而非拼装**：所有组件共享视觉令牌、布局系统、数据服务和设置入口。
5. **本机优先**：配置和个人数据默认保存在本地；网络只用于天气和检查更新；自动检查更新每天最多一次、只查询版本号，可关闭，发现新版本只提示，由用户决定下载安装。
6. **分享外观，不分享隐私**：主题包描述样式、布局和语义槽位，不包含个人内容。
7. **轻量可衡量**：性能目标必须进入验收，不以“看起来轻量”代替测量。

### 5.1 四类能力与统一设计语言

统一视觉不等于把所有模块套进同一种卡片容器。四类能力各自只负责一类核心语义：

- 桌面信息：时间、天气、性能和低干扰的信息层级；
- 桌面分组盒：路径映射、分类和整理操作；
- 冰蓝 Dock：应用启动、运行状态、窗口分组、切换和智能隐藏；
- Windows 原生任务栏适配：保持默认、透明/模糊和智能隐藏策略。

冰蓝桌面统一颜色、材质、字体、间距、圆角级别、动效、编辑状态和设置入口，但允许环境信息表面、工作表面、容器表面和 Dock 使用不同的界面骨架。“苹果式桌面”由顶端信息条、居中冰蓝 Dock 与原生任务栏智能隐藏/透明组合完成：顶端信息条只承载冰蓝自有的时间、待办、天气、性能与只读系统状态（电量、音量、网络、输入法、消息提示），不读取或显示任何应用的菜单，不承载托盘、控制中心或通知中心，也不提供任何系统调节；不修改 Explorer 的开始菜单、托盘、通知和任务栏按钮结构。

桌面内容与设置边界、三种桌面模式和 Dock/任务栏验收门见 [`DESKTOP-SHELL-AND-SURFACES.md`](./DESKTOP-SHELL-AND-SURFACES.md)。

## 6. MVP 范围

### 6.1 纳入 MVP

| 模块 | MVP 能力 | 替代目标 |
| --- | --- | --- |
| 桌面宿主 | 组件布局、拖动、缩放、锁定、显示器与 DPI 恢复 | 既有桌面组件承载 |
| 信息组件 | 时间日期、问候语、天气、CPU/RAM/网络 | 既有桌面信息体验 |
| 待办 | 默认三项、增删改、完成切换、隐藏已完成、本地保存 | 当前任务清单 |
| 普通便签 | 多行纯文本、字体与外观、本地保存 | 自由文本记录 |
| 桌面分组盒 | 桌面入口/文件/文件夹的安全映射、导入、排序、移除映射、缺失提示 | Pogget 的安全子集 |
| Dock | 固定应用、运行中应用、窗口切换、排序、自动隐藏 | Nexus |
| 顶端信息条 | 顶边满宽信息条：时间、待办概要、天气、性能与只读系统状态 | macOS 菜单栏的观感（仅观感，无菜单栏职能） |
| 任务栏外观 | 保持原样、透明/模糊、智能隐藏三种模式 | TranslucentTB |
| 主题系统 | 导入、导出、预览、布局恢复、语义绑定 | 多软件配置分发 |
| 设置与托盘 | 首次引导、统一设置、开机启动、备份恢复、退出 | 四套分散入口 |

### 6.2 明确不纳入 MVP

- 不替换 Explorer、开始菜单、系统托盘、Alt+Tab、虚拟桌面或窗口管理器。
- 不加载或运行第三方皮肤、脚本或配置格式。唯一例外是“从 Rainmeter 皮肤导入外观”：只读取所选皮肤 .ini/.inc 里的字体、文字色、底色与不透明度、强调色和圆角，换算成冰蓝卡片外观并先备份当前设置；不执行度量、脚本或插件，导入后与该皮肤不再关联，本机未安装的字体沿用原字体。
- 不提供任意脚本执行、第三方插件市场或通用皮肤运行时。
- 不做窗口平铺、复杂手势、动态壁纸、桌宠或完整音乐播放器。
- 不做 Nexus 式的复杂粒子、反射、弹跳和重型特效。
- Explorer 内只允许自有任务栏背景适配组件，通过 Windows XAML 诊断接口加载；不修改其他 Shell 表面或系统文件。
- 不自动通过 IP、GPS 或 Wi-Fi 推断位置；MVP 天气使用用户手动选择的城市。
- Metrik 是用户的额外软件，不属于本项目范围。

## 7. 信息架构与关键流程

### 7.1 产品结构

```text
冰蓝桌面
├─ 桌面宿主
│  ├─ 信息组件
│  ├─ 待办
│  ├─ 普通便签
│  └─ 桌面分组盒
├─ Dock
├─ 原生任务栏外观适配
├─ 设置中心
├─ 主题包管理
└─ 托盘与生命周期管理
```

### 7.2 首次使用流程

1. 安装并启动冰蓝桌面。
2. 选择默认主题或导入主题包。
3. 选择显示器和缩放预览。
4. 设置问候姓名和天气城市；明确说明天气数据会联网，城市保存在本地。
5. 为“浏览器、音乐、下载、云盘、聊天”等语义入口绑定本机应用或文件夹。
6. 选择任务栏模式和是否开机启动。
7. 进入桌面；卡片默认可拖动，并可在“桌面组件”页逐张锁定位置。

### 7.3 日常流程

- 普通状态下，桌面组件处于正常窗口层级，不压盖前台应用；系统“显示桌面”（如 Win+D）或“最小化所有窗口”时，桌面组件保持可见。
- 用户通过 Dock 启动或切换应用，通过待办和文件收纳直接处理当天事项。
- 需要调整时直接拖动未锁定卡片；完成后在“桌面组件”页锁定对应卡片，避免误拖动。
- 应用更新或退出前保存状态；异常启动时优先读取有效主配置，否则恢复 `.bak`。

### 7.4 分享主题流程

1. 用户点击“导出主题”。
2. 系统展示将包含和排除的内容。
3. 导出主题样式、组件开关、相对布局和语义槽位。
4. 接收者导入后运行绑定向导，将语义槽位绑定到自己的应用和文件夹。
5. 接收者的姓名、城市、待办、文件映射和路径保持独立。

## 8. 功能需求

### 8.1 应用宿主与生命周期

- **HOST-01** 应用只允许一个主实例，所有模块由同一生命周期管理。
- **HOST-02** 应用只创建一个托盘入口和一个开机启动项。
- **HOST-03** 托盘至少提供：显示/隐藏桌面、桌面组件设置、备份、退出。
- **HOST-04** 普通应用窗口应自然覆盖桌面组件；组件默认不得置于顶层。
- **HOST-05** 全屏游戏或视频期间暂停非必要刷新和动画，并隐藏会干扰全屏的表面。
- **HOST-06** 崩溃后再次启动可以恢复上次有效配置，并清理未完成的临时状态。

### 8.2 布局与窗口

- **LAYOUT-01** 每个组件默认支持从标题或非交互空白区域拖动，并支持逐卡锁定和恢复默认位置。
- **LAYOUT-02** 锁定状态必须清晰可查；复选框、文本输入、新增和删除等交互控件不能成为拖动区域。
- **LAYOUT-03** 保存组件所在显示器、DPI 无关坐标、尺寸、层级和可见状态。
- **LAYOUT-04** 显示器移除、分辨率改变或缩放改变后，组件必须回到最近可用工作区。
- **LAYOUT-05** 普通状态只显示内容与内容动作，不显示拖动手柄、外观、城市或刷新策略等管理控件；未锁定卡片的空白区域负责移动，沿边缘 8 DIP 的窄带和四角负责调整大小。
- **LAYOUT-06** 所有卡片及对应的显示、锁定、外观、尺寸和内容配置由冰蓝桌面 App 的“桌面组件”列表与详情统一承载。
- **LAYOUT-07** 支持对齐参考线、边缘吸附和组件间等距提示；MVP 不需要自由网格编辑器。
- **LAYOUT-08** 主题布局使用相对显示器锚点和安全边距，不能只保存绝对像素。

### 8.3 信息组件

- **WIDGET-01** 提供时间和日期，可设置 12/24 小时制。
- **WIDGET-02** 提供按时段变化的问候语和用户自定义称呼。
- **WIDGET-03** 提供天气城市、当前温度、天气现象、最高/最低温和湿度。
- **WIDGET-04** 天气城市由用户手动搜索选择；无授权的自动定位不进入 MVP。
- **WIDGET-05** 天气数据源采用 Open-Meteo 或经单独评审的等价公开接口，界面显示数据更新时间和刷新状态。城市搜索优先在内置离线城市库本地完成（国内省、市、区县，不联网、不发关键词）；库内没有的境外地名使用 OpenStreetMap Nominatim（可搜到乡镇），遵守其每秒 1 次、带应用标识、不做输入即搜的使用政策，并在使用在线搜索处注明 © OpenStreetMap 贡献者。城市库的数据来源、许可证与生成方式记录在 `docs/CITY-DATA.md`。
- **WIDGET-06** 提供 CPU、RAM、上传和下载速率；数值常驻显示，不依赖鼠标悬停。
- **WIDGET-07** 快捷入口是一排线条图标，默认是此电脑、桌面、文档、下载、图片、回收站。用户可在设置中增删、排序，从预设线条图标中选图标，并把位置改成任意文件夹、程序或文件（最多 12 个）；系统文件夹在点击时查找，自定义路径原样打开。这些路径属于个人内容，不进入主题导出。开启清爽桌面时自动显示快捷入口，保证这些位置仍能一键打开。
- **WIDGET-08** 音频可视化保留为后续独立组件，在四来源核心能力完成后实现；装饰线为可关闭项。两者都不是 MVP 发布阻塞项。

### 8.4.1 普通便签

- **NOTE-01** 普通便签是独立组件，不复用待办的完成状态和复选框。
- **NOTE-02** 支持标题（双击或按 F2）和多行纯文本正文直接编辑、自动换行和去抖保存。
- **NOTE-03** 支持正文的本机字体、字号、颜色、粗体、斜体和对齐。
- **NOTE-04** 支持创建多个便签，并保存每个便签的位置、尺寸、锁定状态和外观。
- **NOTE-05** MVP 不做 Markdown、富文本、附件、云同步或多人协作。

### 8.5 桌面分组盒

- **FILE-01** 用户可把文件或文件夹拖入收纳盒。
- **FILE-02** 默认行为仅记录原路径，不移动、复制、重命名或删除原文件。
- **FILE-03** 双击映射使用系统默认程序打开；文件夹使用 Explorer 打开。
- **FILE-04** 支持排序、移除映射、打开所在位置、刷新图标、修改显示名称和转移到其他收纳盒；显示名称和转移只改变映射，不触碰原文件。
- **FILE-05** 原路径不存在时显示“已失效”，允许重新定位或移除映射；“自动整理”会一并清除所在磁盘可访问但原文件已不存在的映射，磁盘未连接或网络共享离线时保留。
- **FILE-06** 支持创建多个收纳盒并编辑标题。
- **FILE-07** 导出主题时只导出收纳盒的布局和样式，不导出映射路径。
- **FILE-08** 支持从当前用户桌面和公共桌面导入直接子项；该操作只新增映射，不隐藏或移动桌面原项目。
- **FILE-08A** 分组盒“+”必须打开文件、文件夹和桌面导入菜单并反馈结果；“自动整理”作为盒内常驻文字按钮显示，不能只隐藏在右键菜单。
- **FILE-09** 首版桌面入口包含普通路径、`.lnk` 和 `.url`；此电脑、回收站等 Shell 命名空间入口与“清爽桌面”恢复链路一起实现。
- **FILE-10** 文件夹视图首版为只读，真实删除、重命名和移动不进入当前 MVP。
- **FILE-11** 提供用户明确开启的“清爽桌面”：不移动原文件，只在记录原状态并具备恢复链路后隐藏 Windows 原生桌面图标。
- **FILE-12** 清爽桌面开启前补齐此电脑、回收站、下载和桌面目录入口；关闭模式、正常退出、异常恢复和卸载必须恢复进入模式前的图标可见状态。
- **FILE-13** 分组盒内容可按图标瓦片或紧凑列表显示，逐盒选择并持久化；切换只改变显示方式，不影响映射内容和原文件。
- **FILE-14** 分组盒提供默认关闭的“自动刷新”：开启后监听桌面与映射所在目录，新桌面项目自动收纳进已有分组盒（不新建分类盒，下载中的临时文件改名完成后才入盒），确认原文件已删除的映射自动移除；未连接磁盘或离线共享上的映射保留。文件系统事件只作提示，事实以完整扫描为准；关闭时全部监听拆除、零开销。

桌面整理、Pogget 行为取舍、普通便签边界和分阶段验收详见 [`DESKTOP-ORGANIZER-AND-NOTES.md`](./DESKTOP-ORGANIZER-AND-NOTES.md)。

### 8.6 Dock

本产品把 macOS 风格的悬浮应用条命名为“冰蓝 Dock”。它是独立应用表面，不是第二套 Windows 任务栏。

- **DOCK-01** 同时显示固定应用和当前运行的临时应用。
- **DOCK-02** 同一应用的多个顶级窗口按应用分组，并可展开选择。
- **DOCK-03** 点击未运行应用时启动；点击运行应用时聚焦；点击当前前台应用时最小化。
- **DOCK-04** 中键或 Shift+点击启动新实例（应用不支持时允许失败并给出轻提示）；低优先级，不作为 Dock 首版验收项。
- **DOCK-05** 右键菜单提供固定/取消固定、关闭窗口、启动新实例、打开文件位置，以及不在 Dock 中显示某个应用（在 Dock 设置中恢复）。
- **DOCK-06** 支持拖动排序、运行指示、活动窗口指示和轻量悬停放大。
- **DOCK-07** 首版只提供屏幕底边居中和显示器选择；上、左、右边缘作为后续扩展。
- **DOCK-08** 支持智能隐藏，并在最大化或全屏窗口占用相同屏幕时避免遮挡；保留模式下提供默认关闭的“最大化让出底部空间”选项：开启后窗口最大化时释放预留并隐藏 Dock，鼠标移到屏幕底边可临时唤出，窗口还原后自动恢复。Dock 处于隐藏状态时缩成一个可拖动的角落把手：悬停在把手旁展开完整 Dock，把手位置持久保存；真全屏（非最大化铺满）时把手也隐藏。
- **DOCK-09** MVP 不模拟开始菜单、托盘、任务栏跳转列表或系统通知。

### 8.7 原生任务栏外观

本节只描述 Explorer 提供的 Windows 原生任务栏，不包含冰蓝 Dock。

- **TASKBAR-01** 提供“保持系统默认”“透明/模糊”“智能隐藏”三种模式。
- **TASKBAR-02** 只调整原生任务栏外观和可见策略，保留开始菜单、托盘、通知和任务栏按钮。
- **TASKBAR-03** 退出、崩溃恢复和卸载时恢复进入应用前的任务栏状态。
- **TASKBAR-04** 不支持的 Windows 版本或 Explorer 状态下必须回退到系统默认，而不是持续重试。
- **TASKBAR-05** 任务栏适配必须是可关闭、可隔离的高风险模块，故障不能拖垮其他桌面组件。
- **TASKBAR-06** 任务栏透明允许通过 Windows XAML 诊断接口向当前用户的 Explorer 加载自有原生组件，仅改变经过识别的任务栏背景；不修改系统文件、不执行脚本、不要求管理员权限。
- **TASKBAR-07** “Windows 原生”“冰蓝混合”“苹果式”是 Dock 与原生任务栏两套独立状态的安全编排，不得把两者实现为互相覆盖的同一模块。
- **TASKBAR-08** Windows 原生自动隐藏开启时，桌面组件不得占用对应显示器的任务栏唤出边缘；边缘保护只能查询系统状态和约束冰蓝组件，不得修改 Windows 自动隐藏开关。
- **TASKBAR-09** 不做窗口状态联动样式（如最大化时变不透明、开始菜单打开时变色）、每显示器独立样式和任意自定义颜色；MVP 只提供三种静态模式。
- **TASKBAR-10** 自动隐藏使用文档化 AppBar API（`ABM_SETSTATE`）；透明使用按 Windows Build 和元素结构校验的 XAML 组件，宿主退出或失联时恢复背景；模糊使用系统窗口材质。未知版本、组件缺失或恢复未确认时保持系统默认。

### 8.8 主题包

- **THEME-01** 主题包至少包含清单、视觉令牌、组件开关、相对布局、Dock 结构、图标覆盖和预览图。
- **THEME-02** 清单包含主题 ID、名称、作者、主题版本和最低应用版本。
- **THEME-03** 视觉令牌包含颜色、透明度、模糊、圆角、阴影、字体引用、间距和动画强度。
- **THEME-04** 应用绑定使用语义槽位，例如 `browser`、`music`、`downloads`、`cloud-drive`、`chat`。
- **THEME-05** 主题包不得包含姓名、城市、待办、文件映射、绝对路径、令牌或其他私人数据；顶端信息条只携带其可分享设置（开关、显示方式、模块开关、外观），显示器标识属于本机设置不进主题包。
- **THEME-06** 导入前校验结构、版本和资源大小；未知字段可忽略，危险内容拒绝加载。
- **THEME-07** 主题包不允许携带或执行任意脚本。

建议的主题包结构：

```text
ice-blue-theme.zip
├─ manifest.json
├─ tokens.json
├─ layout.json
├─ bindings.json
├─ assets/
│  ├─ wallpaper.jpg
│  ├─ preview.png
│  └─ icons/
└─ fonts/                 # 仅在授权允许重新分发时存在
```

### 8.9 设置、备份与卸载

- **SETTINGS-01** 设置中心按外观、桌面组件、Dock、任务栏、通用分类，同一设置只在一个页面出现（桌面模式只是同时设置 Dock 与任务栏的快捷方式）；设置修改后立即生效。
- **SETTINGS-02** 设置变更尽量实时预览；高风险项提供应用/取消和恢复默认。
- **SETTINGS-03** 个人状态与主题定义分开存储，并使用带版本号的结构。
- **SETTINGS-04** 保存采用临时文件替换并保留最近有效 `.bak`；支持手动备份和恢复。
- **SETTINGS-05** 卸载时允许保留或删除用户数据；无论选择哪项都必须恢复任务栏和移除启动项。
- **SETTINGS-06** “桌面组件”页以组件列表和详情统一承载所有卡片设置；从桌面卡片进入时直接选中对应项，不使用桌面悬浮设置窗或组件下拉框。
- **SETTINGS-07** 每个组件可独立选择卡片文字颜色，提供白色、黑色快捷项和自定义颜色，并与其他外观状态一起持久化。

### 8.10 顶端信息条

本节描述“顶端信息条”：贴住所选显示器顶边的满宽信息条，macOS 菜单栏的观感，但不承担菜单栏的任何职能。

- **TOPBAR-01** 只承载冰蓝自有数据与只读系统状态，不读取或显示任何应用的菜单，不承载系统托盘图标、控制中心、通知中心，不读取系统通知。
- **TOPBAR-02** 九个模块：时钟+日期、待办概要（未完成计数）、天气、性能、电量、音量（只读）、网络、输入法（布局级，不读 IME 内部中/英状态）、消息提示（复用应用闪烁信号，无角标数，点击聚焦该应用）。
- **TOPBAR-03** 模块独立开关、默认全开、顺序固定；待办概要点击弹出待办清单（信息栏形式，条目可点击切换完成状态并与桌面待办卡联动），消息提示点击聚焦该应用，性能点击打开任务管理器并停留性能页，电量/网络/音量点击唤起任务栏托盘的快速设置弹层，时钟点击弹出顶栏自己的只读月历（时间、今天日期、可翻月的月视图），输入法点击深链到对应设置；天气为纯展示（悬停展示高低温、湿度、更新时间与失败状态）；交互热区不小于 32×32 DIP。
- **TOPBAR-04** 两种显示方式可配、默认“始终显示并预留顶边空间”（AppBar 顶边预留，预留高度为条高减 1 像素，最大化窗口顶边贴入信息条最后一行下方）；或“智能隐藏”（贴顶边唤出、延迟收回）；常驻悬浮盖窗口不提供；真全屏按 Dock 规则退避；顶边被系统任务栏占用（Windows 10）时自动回退智能隐藏。
- **TOPBAR-05** v1 单显示器可选、默认主屏；多显示器各自显示留作后续扩展（Schema 预留）。
- **TOPBAR-06** 顶栏默认关闭；“苹果式”桌面模式把它编排为开启并关闭时间/天气/性能三张桌面信息卡（数据不重复显示）；其余模式与全部布局预设不触碰顶栏；模式回显不把顶栏纳入判定。
- **TOPBAR-07** 退出、崩溃与强杀后必须释放预留的屏幕空间；Explorer 重启后重放仍然有效的预留。
- **TOPBAR-08** 主题包携带顶栏的可分享设置（开关、显示方式、模块开关、外观），显示器标识不导出。

## 9. 视觉与交互基线

默认主题延续当前冰蓝桌面：高透明度白字、克制的浅蓝强调、壁纸背景上的玻璃容器和轻阴影。

- 默认字体优先使用系统可用的 `Segoe UI Variable` / `Microsoft YaHei UI`，特殊标题字体只能作为主题资源且需要授权。
- 正文、数值和交互标签必须保持可读，不应通过降低透明度追求“更融入壁纸”。
- 交互热区至少 32 × 32 DIPs；图标视觉尺寸可以更小。
- 组件动画短、轻、可关闭；遵循系统“减少动画”偏好。
- 键盘可完成新增、编辑、勾选、删除、移动焦点和关闭弹层。
- 玻璃效果不可用时回退到半透明纯色，不允许内容消失或变成乱码。

当前 Pogget 视觉测量和 WPF 还原依据见 `design-lab/DESIGN-SPEC.md`，它只约束桌面分组盒和既有材质研究，不是全产品视觉母版或产品范围定义。

| --- | --- | --- |
| 视觉令牌与布局 | 本地主题目录 | 是 |
| 姓名、城市与应用绑定 | 本地个人设置 | 否 |

### 10.2 隐私规则

- 默认不采集遥测，不上传待办、路径、应用列表或窗口标题。
- 城市搜索优先在内置离线城市库本地完成，不发关键词；本地无匹配时才在用户主动提交下把关键词发送给在线搜索服务。天气请求只发送用户选择城市对应的必要坐标，不使用 IP/GPS/Wi-Fi 或设备位置自动定位。
- 界面明确展示天气数据源、最后更新时间和刷新失败状态。
- 后续若增加崩溃报告，必须单独选择加入并在发送前展示内容范围。

## 11. 技术方案与边界

### 11.1 延续现有方案

- 使用仓库现有的 .NET 10 和 WPF，不在 MVP 中迁移到 Electron、Tauri 或自研渲染引擎。
- 保留 `BingLan.App`（WPF/Windows 集成）与 `BingLan.Core`（模型、规则、持久化）边界。
- 在一个应用进程内使用共享服务采集性能、天气、窗口状态和主题状态，避免每个组件单独轮询。
- 使用事件驱动更新；只有时钟、性能和必要动画采用节流后的周期刷新。

### 11.2 建议的逻辑分层

```text
BingLan.App
├─ ShellHost               # 单实例、托盘、生命周期
├─ DesktopHost             # 组件窗口、布局、DPI
├─ DockHost                # AppBar、窗口列表、激活与分组
├─ TaskbarAdapter          # 可选、隔离、可恢复
└─ Settings                # 首次引导与统一设置

BingLan.Core
├─ Models                  # 版本化状态与主题模型
├─ Services                # 待办、文件映射、天气、性能、绑定
├─ Themes                  # 校验、导入、导出、迁移
└─ Persistence             # 原子保存、备份、恢复
```

### 11.3 外部实现参考与许可证策略

- 阶段 0 已决定 Dock 不直接引入 [ManagedShell](https://github.com/cairoshell/ManagedShell)，而采用最小自有 Win32 适配层。原因是 ManagedShell 的任务服务包含 Shell 替代场景所需的全局行为，与本产品“桌面伴侣而非 Shell”的边界不一致。可运行证据、API 依据与剩余风险见 [`design-lab/BingLan.DockSpike/README.md`](../design-lab/BingLan.DockSpike/README.md)。
- PoggetCore 只用于理解“容器 + 路径映射”模型，不把其不完整 GUI 架构搬入应用。
- 第三方桌面美化项目可用于理解产品行为和 Windows 边界；任何 GPL/AGPL 代码或资产不得复制到当前项目，除非项目整体许可证策略先被明确修改。
- 对没有明确许可证的仓库，只研究公开行为和界面，不复制代码、图标、着色器或资源。
- 所有新依赖在引入前记录：用途、版本、许可证、替代方案、打包体积和运行时成本。

## 12. 交付阶段

目标：在扩展产品前证明 Dock 和多屏布局可以可靠实现。

目标：在保留 Windows 原生任务栏的前提下替代 TranslucentTB。

当前状态：保持默认、透明、模糊、自动隐藏和三种桌面模式已进入正式应用，默认保持系统默认；透明模式在 Build 26200 上已通过自有 XAML 组件实现，并验证切回默认、宿主异常退出、恢复命令及重复启停；模糊保留系统材质。自有组件的真实 Explorer 重启、多显示器和安装升级/卸载矩阵尚未完成，见 [`TASKBAR-QA.md`](./TASKBAR-QA.md)。

### 阶段 4：分发与朋友测试

目标：把“自己能用”变成“别人能装”。

当前状态：开机启动开关、手动备份与从备份恢复已进入设置中心；按用户安装的 setup.exe 已在本机完成安装、启动、卸载和数据保留/移到回收站验证（卸载时恢复任务栏并删除启动项），见 [`INSTALLER.md`](./INSTALLER.md)。主题包导出导入已提供：包含经校验的清单、视觉令牌（颜色、透明度、圆角、字体引用、文字阴影、吸附间距、Dock 动效，以及作为模糊的任务栏透明/模糊材质）、组件开关、相对布局、Dock 应用槽位与自定义图标和按布局绘制的示意预览图，导入前可预览，未匹配的应用槽位通过绑定向导逐个选择或跳过；壁纸和字体不打包，由用户自行添加。首次引导已包含 Dock 显示器选择（显示分辨率与缩放）和“下载”入口文件夹绑定。

- 单一安装包、主题导入导出、绑定向导、干净升级与卸载。
- 至少 3 台不同缩放/显示器配置的 Windows 11 设备测试。
- 记录从安装到完成桌面的耗时和阻塞点。

退出标准：没有开发环境的用户可在 5 分钟内完成首次配置。

## 13. 非功能需求与性能预算

以下是 MVP 的阶段性工程预算，不是已经验证的承诺；阶段 0/1 应建立基准并根据真实数据修订。

| 指标 | 预算 |
| --- | --- |
| 常驻进程 | 1 个主进程；必要的系统子进程必须说明原因 |
| 开机启动项 | 1 个 |
| 稳态工作集 | 小于 150 MB |
| 空闲 CPU 中位数 | 小于 0.5% |
| 首次可见时间 | 小于 2.5 秒 |
| 天气刷新 | 默认不高于每 15 分钟一次，失败指数退避 |
| 性能采样 | 默认 1 秒一次，隐藏/全屏时降低频率 |
| 状态保存 | 用户操作后去抖保存，退出前强制落盘 |
| 平台 | Windows 11 x64；100%/125%/150% 缩放优先。Windows 10 2004 及以上尽力支持：任务栏外观不可用、设置窗口无 Mica、系统窗口为直角 |

当前四软件组合曾观察到约 357.6 MB 工作集；该数字只作为替代前的单次参考，后续必须用统一场景重新测量。

2026-09-28 本机测量（Windows 11 build 26200，NVIDIA 独显，冰蓝桌面单进程，1 个信息层、1 个待办、1 个分组盒，Dock 关闭，启动 40 秒后取 3 次平均）：工作集 57–66 MB，其中私有工作集约 28–33 MB，私有提交约 90 MB，90 秒内无增长。同一会话较早的几次测量曾为 153–160 MB，私有提交同样约 90 MB，差值来自共享页（显卡驱动 DLL 映射约 110 MB），推测与显卡着色器编译和窗口可见状态有关，尚未定位。关闭并发 GC、`ConserveMemory` 和关闭 TieredPGO 均无可测收益（差异在 ±5 MB 噪声内），因此未改运行时配置。

## 14. MVP 验收清单

### 安装与恢复

- [ ] 一个安装包完成安装、更新和卸载。
- [ ] 任务管理器中只有一个常驻主进程，启动应用中只有一个冰蓝桌面条目。
- [ ] 异常终止后重启不会丢失最近有效配置。
- [ ] 退出和卸载后任务栏恢复，启动项清理。

### 核心体验

- [ ] 默认主题安装后完整显示，布局不会越过屏幕工作区。
- [ ] 待办可新增、编辑、完成/取消完成、排序和删除。
- [ ] 文件拖入只建立映射，删除映射不影响原文件。
- [ ] 天气显示正确城市、更新时间和失败状态。
- [ ] CPU、RAM、上传和下载数值无需悬停即可阅读。
- [ ] Dock 能启动、聚焦、最小化和分组常见桌面应用。
- [ ] 最大化和全屏场景下 Dock 与组件不会遮挡主要内容。

### 分享与隐私

- [ ] 导出的主题可在另一台电脑导入。
- [ ] 导入后通过绑定向导完成本机应用关联。
- [ ] 检查主题包内容，确认不包含姓名、城市、待办、文件路径和令牌。
- [ ] 除天气和每日一次的版本检查外没有后台网络请求；关闭自动检查更新后只剩天气。

### 兼容性与性能

- [ ] 在 100%、125%、150% 缩放下完成核心流程。
- [ ] 在主副屏切换、显示器断开和 Explorer 重启后恢复。
- [ ] 达到或明确修订第 13 节性能预算，修订必须附测量数据。

## 15. 风险与决策门

| 风险 | 影响 | MVP 处理 |
| --- | --- | --- |
| Windows 更新改变任务栏内部行为 | 任务栏透明或隐藏失效 | 独立适配器、版本检测、失败回退、最后实施 |
| Dock 的窗口归属和 UWP/PWA 分组复杂 | 启动/切换行为不一致 | 阶段 0 用常见应用矩阵验证 |
| WPF 透明窗口与混合 DPI | 布局漂移、点击偏移 | 使用 DIPs、每显示器 DPI、工作区恢复测试 |
| 玻璃模糊和大量透明窗口成本 | GPU/内存上升 | 统一材质、减少窗口数量、可关闭模糊/动画 |
| 主题分享携带本机信息 | 隐私泄露或路径失效 | 主题与个人状态分离、语义绑定、导出审计 |
| 开源参考许可证不兼容 | 无法安全分发 | 只采纳兼容依赖；GPL/AGPL 项目仅作行为研究 |

进入实现前必须完成三项决策：

1. Dock 窗口跟踪采用最小自研 Win32 封装（已决策；生产合并前完成按实际硬件收缩后的阶段 0 矩阵）。
2. 任务栏透明/智能隐藏在目标 Windows 11 版本上的稳定实现边界。
3. 主题包是否内嵌壁纸和字体，以及相应资源授权规则。
