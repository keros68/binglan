# 桌面整理盒与便签产品定义

> 文档状态：阶段 1 功能边界与实现顺序  
> 版本：0.3  
> 更新日期：2026-08-04  
> 关联基线：[`MVP-PRODUCT-DESIGN.md`](./MVP-PRODUCT-DESIGN.md)

## 1. 产品决策

冰蓝桌面不做 Pogget 的逐项复刻。用户真正需要的是把三类内容放进同一套桌面组件语言中：

1. **桌面分组盒**：把应用快捷方式、URL、文件和文件夹组合成可自定义分类；
2. **待办**：管理有完成状态和顺序的行动项；
3. **普通便签**：保存不需要勾选的多行文字。

三者共享窗口拖动、缩放、锁定、透明材质、字体、圆角和本地保存，但内容模型与交互语义保持独立。待办不承担长文本便签，桌面分组盒也不伪装成文件管理器。

## 2. 从 Pogget 借鉴什么

Pogget 的现有产品实际包含四种不同能力：

| Pogget 能力 | 实际语义 | 冰蓝 MVP 决策 |
| --- | --- | --- |
| 映射收纳盒 | 保存路径引用，移除条目不删除源文件 | 作为桌面分组盒默认模式 |
| 普通收纳盒 | 把文件真实移动到应用托管目录 | 不纳入当前 MVP |
| 目标文件夹盒 | 直接展示并修改一个真实目录 | 先做只读文件夹视图，写操作后置 |
| 文件夹内联浏览 | 在组件中进入子目录、搜索和返回 | 排在分组闭环之后 |

本机 Pogget 数据也表明，当前截图中的普通盒通过把文件移入应用托管目录来真正清空桌面，并不只是映射。冰蓝当前的产品与仓库安全边界要求“不修改桌面文件真实位置”，所以不能把这部分行为暗中复制进来。

公开资料和研究入口：

- [Pogget 映射收纳说明](https://docs.vilinko.com/docs/pogget/mapping.html)
- [Pogget 官网](https://pogget.vilinko.com/)
- 本仓库只读研究材料：`upstream/PoggetCore`

## 3. 桌面分组盒

### 3.1 核心任务

用户可以建立“工作”“常用软件”“近期材料”等多个盒子，把桌面入口与真实文件放在同一视觉分组中。盒内移动、排序、改显示名称都只改变冰蓝的本地状态，不改变原文件。

首版支持的项目类型：

- 普通文件；
- 文件夹；
- 应用和文档快捷方式（`.lnk`）；
- URL 快捷方式（`.url`）；
- 可执行文件。

“此电脑”“回收站”等 Shell 命名空间项目没有普通磁盘路径，首版不纳入，也不伪造成文件路径。

当前一键整理采用可解释的安全分类：目录进入“桌面文件夹”；`.lnk`、`.url`、`.exe`、`.com`、`.bat`、`.cmd` 和 `.appref-ms` 进入“软件与快捷入口”；其余普通路径进入“桌面文件”。分类只创建或补充路径映射，不解析或执行快捷方式，也不改变 Windows 桌面原项目。

### 3.2 内容模式

#### 手动分组 `ManualMappings`

这是默认且优先完成的模式。用户拖入项目或从桌面导入时，只保存规范化后的路径引用。

- 可手动排序，也可按名称、类型或修改时间排序；
- 可把映射转移到另一个盒子；
- 可设置仅影响显示的别名；
- 支持打开、打开所在位置、刷新图标、移除映射；
- 路径不存在时显示“已失效”，可重新定位或移除；
- 拖入文件夹只映射文件夹本身，不递归导入内容。

#### 桌面总览 `DesktopOverview`

合并只读展示当前用户桌面与公共桌面的直接子项。用户可以把选中项目“加入分组盒”，该操作仍只新增映射。

默认映射模式不会隐藏 Windows 桌面图标、改变图标坐标或自动删除桌面条目。因此，未开启“清爽桌面”时，同一项目可能同时出现在 Windows 桌面和分组盒中；界面必须如实说明原文件仍保留在桌面路径。

#### 文件夹视图 `FolderMirror`

只读展示一个用户选择目录的直接子项。首版支持打开、打开所在位置、刷新和加入分组，不提供删除、重命名或移动源文件。

目录扫描、元数据读取和批量图标提取在后台完成。稳定基线使用手动刷新和窗口重新激活刷新；`FileSystemWatcher` 只能作为更新提示，不能作为唯一事实来源。

#### 清爽桌面 `CleanDesktop`

“清爽桌面”是用户明确开启的可逆显示模式，不是文件移动功能。开启前记录 Windows 原生桌面图标可见状态，补齐此电脑、回收站、下载和桌面目录等系统入口，然后隐藏原生桌面图标，只显示冰蓝整理盒。

- 原文件和文件夹继续保留在原桌面路径；
- 新增桌面项目通过文件系统事件提示和低频完整扫描对账；
- 正常退出、异常恢复、关闭该模式和卸载必须恢复进入模式前的图标状态；
- 如果目标 Windows 版本无法通过可靠、可恢复的方式控制图标可见性，功能必须回退默认映射模式；
- 不得通过 Explorer DLL 注入、Shell 替换或强制结束 Explorer 实现。

Shell 写入、检查点、异常恢复语义和阶段 0 真机门详见 [`DESKTOP-CLEAN-MODE-TECHNICAL-DESIGN.md`](./DESKTOP-CLEAN-MODE-TECHNICAL-DESIGN.md)。

### 3.3 关键交互

- 双击标题或按 F2 修改盒子标题；
- 标题栏“+”打开选择文件、选择文件夹和导入桌面的明确菜单；取消选择不改变映射，导入完成后显示新增数或无新项目反馈；
- 盒子底部常驻“自动整理”按钮，右键菜单只作为补充入口；按钮文案和提示必须说明只建立映射、不移动原文件；
- 未锁定时，标题栏空白区和组件空白区都可直接拖动；
- 锁定只禁止移动和缩放，不影响打开、编辑标题和右键操作；
- 双击条目使用系统默认行为打开；
- “移除映射”只从盒内移除，不触碰磁盘；
- 排序和盒间转移使用“映射”“分组”等词，不能写成“移动文件”；
- 大批量导入先显示数量与来源，完成后显示新增数和重复数。

### 3.4 当前 MVP 不做

- 不自动移动、复制、重命名、覆盖或删除真实文件；
- 不改变 Windows 桌面图标坐标；除用户明确开启且可恢复的“清爽桌面”外，不修改图标可见状态或其他 Explorer 设置；
- 不替换 Explorer，不注入 DLL；
- 不做盒内嵌套盒、标签规则引擎和自动文件归档；
- 不把视图排序宣传成磁盘目录的物理顺序。

## 4. 待办

待办只服务有完成状态的行动项：

- 新建组件默认保持空列表；
- 点击文字编辑，点击方框切换完成状态；
- 完成后变淡并划线，可隐藏或保留；
- 支持新增、删除、手动排序；
- 标题、条目、顺序和完成状态本地保存。

交互控件行为必须单一：方框只切换状态，“×”只删除整条，“+”只新增并聚焦，不显示“点击文字编辑”等说明文案。

## 5. 普通便签

普通便签是独立组件，不在待办中增加“便签模式”。首版使用纯文本多行编辑：

- 可创建多个便签；
- 正文点击后直接编辑，标题双击或按 F2 编辑；
- 正文自动换行，失焦或去抖保存；
- 支持正文的本机字体、字号、颜色、粗体、斜体和对齐；
- 支持与其他组件一致的背景、标题栏、透明度、圆角、锁定和布局保存；
- 不显示复选框、完成数、隐藏已完成等任务语义。

首版不做 Markdown、富文本混排、附件、云同步、多人协作和网页剪藏。

## 6. 设置与视觉规则

- 卡片外观和尺寸在冰蓝桌面 App 的“桌面组件”页设置，桌面上不展开设置窗；
- 标题栏和条目卡片圆角由外圆角派生，不提供第二组持久化设置；
- 外圆角为 `0` 时内部全部为直角，内部圆角始终小于外轮廓；
- 同类组件共享默认冰蓝令牌，但每个组件可单独调整外观；
- 每个组件可独立选择卡片文字颜色，并提供白色、黑色快捷项与自定义颜色；普通便签正文仍保留自己的排版颜色设置；
- 设置、输入框、复选框、图标和菜单不得误触发窗口拖动。

## 7. 数据模型方向

后续状态迁移从 Schema v6 开始，旧 `FileBoxes` 原样保留：

```text
DesktopGroupBoxState
├─ Id / Title / Placement / IsLocked
├─ Appearance / CornerRadius
├─ ContentMode
├─ SourceFolder?                 # 仅 FolderMirror
├─ SortMode
└─ Items[]
   ├─ Path / DisplayName?
   └─ Order

NoteWidgetState
├─ Id / Title / Content
├─ Placement / IsLocked
├─ Appearance / CornerRadius
└─ BodyTypography
```

个人状态包含待办、便签正文、映射路径和来源目录，不得进入主题包。主题只保存可分享的视觉令牌、相对布局和组件类型。图标与文件元数据属于可丢弃缓存。

## 8. 交付顺序与验收

### P0：当前组件体验

- 卡片外观在“桌面组件”页设置并即时生效；
- 外圆角调整时标题栏与内容卡片同步；
- `0 / 3 / 7 / 15.5 / 32 DIP` 均无双层漏角；
- 未锁定空白区可拖动，锁定后内容操作仍可用。

### P1：手动桌面分组闭环

- 从托盘或组件右键菜单一键生成或复用软件、文件夹和文件分类盒；
- 支持拖入和从用户/公共桌面导入；
- 支持手动、名称和类型排序；
- 重启后分类、顺序和标题保持；
- 导入、排序、移除前后，原文件路径、大小和修改时间不变。

当前实现状态：P1 已具备可见“自动整理”按钮、一键安全分类、明确的文件/文件夹/桌面添加菜单、导入结果反馈、拖入、桌面直接子项导入、去重、手动/名称/类型排序和分类身份持久化。

### P2：分组管理完整性

- 盒间转移映射、显示别名、打开所在位置；
- 缺失状态、重新定位和异步图标加载；
- 大批量桌面导入时界面不卡顿。

当前实现状态：P2 已具备盒间转移映射、显示别名、打开所在位置、缺失状态、重新定位和后台图标加载；大批量导入的流畅度尚未测量。

### P3：普通便签

- 多行文本、字体与外观、位置和尺寸重启后恢复；
- 不出现待办语义；
- 主题导出不包含标题或正文。

### P4：只读桌面总览与文件夹视图

- 正确展示直接子项并可刷新；
- “加入分组”只新增映射；
- 应用内不存在修改镜像源文件的操作。

## 9. 物理收拢的未来决策门

仅做映射无法真正清空 Windows 桌面，因为原文件仍在桌面。若未来要加入 Pogget 式“收拢桌面文件”，必须作为独立、显式、可撤销的高风险功能重新立项，并至少满足：

1. 操作前显示完整清单、目标目录和重名策略；
2. 仅允许处理用户明确选择的桌面直接子项；
3. 预检磁盘根目录、父子路径重叠、跨卷移动和目标冲突；
4. 使用两阶段提交、操作日志和可恢复备份；
5. 提供“归位”，且与“移除映射”“删除文件”使用完全不同的按钮和文案；
6. 经过独立测试与产品确认后，才允许突破当前“不移动真实文件”的 MVP 边界。
