# 顶端信息条设计决策

状态：v2.1，2026-10-10 独立复核并完成实施后回写（v1 复核 16 项发现全部闭环；实施偏差见修订记录）。
范围：屏幕顶边的冰蓝信息条表面——角色边界、形态、显示模式、内容模块、交互、设置与持久化、预设编排、实施边界、验证矩阵与文档同步。

## 1. 结论

顶端信息条是一条贴住所选显示器顶边的满宽玻璃横条，只承载冰蓝桌面自有数据（时钟、待办概要、天气、性能、电量、音量、网络、输入法、消息提示）。它承载的内容语义仍属"桌面信息"，容器形态上是 Dock 与桌面组件之外的新表面类型，将作为新的一行加入 [`DESKTOP-SHELL-AND-SURFACES.md`](./DESKTOP-SHELL-AND-SURFACES.md) §3 表面类型表。

它**不是** macOS 菜单栏的复刻：

- 不显示、不读取任何前台应用的菜单（不做 macOS 左侧应用菜单栏）；
- 不承载系统托盘图标、控制中心、通知中心或 Spotlight；
- 不读取系统通知，消息提示不提供角标数；
- 只读展示系统状态（电量/音量/网络/输入法），不提供任何调节弹层。

对 [`DESKTOP-SHELL-AND-SURFACES.md`](./DESKTOP-SHELL-AND-SURFACES.md) §7"不创建 macOS 任务栏替代品"的边界因此保持成立：顶端信息条不替代任务栏的任何职能，也不模拟菜单栏的任何交互，它只是把既有桌面信息换了一种边缘容器。

## 2. 需求决策清单

| # | 决策点 | 结论 |
| --- | --- | --- |
| 1 | 角色 | 冰蓝信息条，只承载自有数据；应用菜单栏/托盘/控制中心/通知中心全部否决 |
| 2 | 显示模式 | "始终显示并预留顶边空间"（默认）/"智能隐藏"两种可配；常驻悬浮盖窗口被否决（违反"最大化应用不能被无意遮挡"） |
| 3 | 内容 | 九模块（见 §4），独立开关，默认全开，全部只读 |
| 4 | 显示器 | v1 单显示器可选、默认主屏；Schema 预留多显示器扩展 |
| 5 | 交互 | 模块点击深链到设置；消息提示例外（点击聚焦应用）；天气 tooltip；统一右键菜单；热区 ≥ 32×32 DIP |
| 6 | 预设 | 顶栏默认关闭；桌面模式"苹果式"升级为顶栏开 + 时间/天气/性能卡关 + Dock 开 + 任务栏智能隐藏（任务栏语义沿用既有定义，不改透明；v1 曾误写"透明"，见修订记录 R1） |
| 7 | 形态 | 满宽贴边直角，高 32 DIP 固定；材质跟随"外观"页，可自定义 |
| 8 | 设置 | 设置中心新增"顶端信息条"页，与"Dock"页平级 |

派生决策（按既有规则推导，未单独追问）：顶栏不提供 Dock 式"最大化让出空间"选项——预留模式的语义就是常驻，需要让路时用户应选智能隐藏；顶栏智能隐藏不引入角落把手（满宽贴边无拖动概念），只用顶边唤出区。

## 3. 表面定义

### 3.1 形态

- 满屏宽、贴死所选显示器顶边、无圆角（不使用卡片圆角令牌），高度固定 32 DIP，不开放高度设置。
- 材质为冰蓝半透明玻璃，浓度与配色默认跟随"外观"页，可在"顶端信息条"页切换为自定义（复用 Dock 的外观自定义模式：`FollowCardLook` + 配色/不透明度）。
- 文字沿环境信息层裸文字规则：白字 + 轻微暗影；模块内数值可使用冰蓝强调色；玻璃不可用时回退半透明纯色。
- 智能隐藏唤出时为同款满宽条，临时浮于窗口上方。

### 3.2 显示模式

- **始终显示并预留顶边空间**：通过 AppBar 预留所选显示器顶边（机制与 Dock 底边预留同源），所有最大化的窗口从横条下方开始；真全屏应用运行时横条按 Dock 的全屏规则退避隐藏，全屏结束后恢复。
- **智能隐藏**：复用 Dock 的智能隐藏状态机（`DockAutoHideState`：贴边唤出、延迟收回、最大化窗口占用同屏时保持隐藏）；唤出区几何为新增的顶边镜像分支（现有 `DockRevealRules.IsInRevealZone` 为纯底边几何，顶栏贴边无需悬空延伸）；真全屏时唤出区同样禁用（对齐 Dock 的"真全屏"例外）。
- 两种模式切换立即生效；智能隐藏切回预留时重新注册 AppBar。

### 3.3 边缘冲突与回退

- 所选显示器顶边已被系统任务栏占用（Windows 10 允许任务栏移到顶部；Windows 11 固定底部）时，不允许进入预留模式，自动回退智能隐藏并在设置页说明。
- 与第三方 AppBar 程序冲突时，对齐 Dock 规则：优先回退为隐藏，不抢占。
- 原生任务栏底部自动隐藏开启时（TASKBAR-08），顶栏不涉及底边，无需边缘保护；若未来顶栏与任务栏同边共存，按 TASKBAR-08 唤出边缘保护处理。

### 3.4 全屏、显示桌面与恢复

- 真全屏（判定对齐 `DockVacateRules.IsTrueFullScreen`：铺满显示器且非最大化的窗口）：两种模式下顶栏都隐藏，不遮挡全屏内容。
- "显示桌面"（Win+D/最小化所有窗口）：顶栏不加入 `DesktopSurfaceWatcher`——预留态顶栏常驻置顶带（与任务栏/Dock 同层），Win+D 的 Progman 抬升盖不住置顶带，沿 Dock 先例无需守护；智能隐藏态收回时本就不可见（实现偏差，随 QA 记录）。
- Explorer 重启：对齐 Dock 的 Explorer 重启恢复路径（`TaskbarCreated` 消息触发），重放仍然有效的预留与显示状态。
- 显示器断开或不可用：所选显示器消失时顶栏回落到主屏（对齐 Dock 的显示器恢复规则：所选 → 主屏 → 任意可用）；显示器恢复后回到所选位置。
- 应用退出、崩溃或宿主进程结束时释放预留的屏幕空间（对齐 Dock 的强制结束恢复验证）。

## 4. 内容模块（九个）

固定布局：左起依次为待办概要、天气、性能；右端最右为时钟+日期，其左依次为消息提示、输入法、音量、网络、电量。顺序固定，不提供拖拽排序。模块间距与内边距沿设计令牌。

| 模块 | 内容 | 数据来源 | 点击行为 |
| --- | --- | --- | --- |
| 时钟+日期 | 日期 + 星期 + 时间，12/24 小时制沿用时间日期组件设置（`InformationWidgetState.Use24HourClock`） | 共享性能采样快照回调（现有机制：时钟与性能同回调）；顶栏可见时计入可见消费者、采样保持正常节拍，顶栏隐藏或真全屏时随全局降频 | 打开"桌面组件"页并选中时间日期 |
| 待办概要 | "待办 N"（全部待办组件未完成项总数） | 待办状态聚合（**新增**，读现有待办持久化） | 打开"桌面组件"页待办区域（多卡时选中第一张） |
| 天气 | 城市 + 当前温度 + 现象 | 天气共享服务（15 分钟节奏） | 打开"桌面组件"页并选中天气；悬停 tooltip 显示最高/最低温、湿度、数据更新时间与失败状态（承接 WIDGET-05 的更新时间可见性要求） |
| 性能 | CPU / RAM / ↑↓ 速率紧凑单行 | 共享性能采样快照（1 秒节流，随全局降频） | 打开"桌面组件"页并选中性能 |
| 电量 | 图标 + 百分比 + 充电态 | `GetSystemPowerStatus`（**新增**，App 层） | 打开"顶端信息条"页 |
| 音量 | 音量百分比（只读） | `IAudioEndpointVolume` 查询，随共享采样回调在后台线程读取（**新增**，App 层 COM，只读；事件回调暂缓——共享节拍已满足"不新增计时器"的意图） | 打开"顶端信息条"页 |
| 网络 | 连接状态 + 类型（WLAN/以太网/未连接） | `NetworkChange` 事件 + 共享采样回调低频校验（**新增**；SSID 需原生 WiFi API，后补） | 打开"顶端信息条"页 |
| 输入法 | 当前键盘布局名（如"Chinese (Simplified) - US Keyboard"），随前台窗口变化 | 前台窗口变化即时刷新 + 共享采样回调低频校验 + `GetKeyboardLayout` 与注册表布局名（**新增**；无系统级输入语言广播，切换输入法但前台不变时最长延迟数秒） | 打开"顶端信息条"页 |
| 消息提示 | 请求注意的应用图标，按请求先后排列，最多显示 3 个，超出折叠为 "+N" | Shell 钩子闪烁信号（`RegisterShellHookWindow` + `HSHELL_FLASH`，即 Dock 橙色标记同源；Core 侧 `DockAttention` 现为无序集合，**需新增有序跟踪**） | **聚焦该应用**（聚焦行为与 Dock 一致；不含 Dock"前台应用再点最小化"规则——顶栏仅在应用请求注意时显示图标） |

采样与节流约束（沿 AGENTS §4 与共享采样契约"禁止各自创建计时器"）：

- 电量、网络的低频读取并入既有 `IPerformanceSamplingService` 快照回调（内部按各自周期抽样，不新建计时器）；网络优先事件驱动。
- 音量用 `IAudioEndpointVolume` 事件通知，输入法用前台与输入语言事件；均不轮询。
- 顶栏隐藏（智能隐藏收回或真全屏退避）时暂停全部模块的 UI 投影更新，恢复显示时立即刷新一次。
- 输入法只到**布局级**：不读取 IME 内部的中/英转换状态（需 TSF 深读，跨输入法不可靠）。
- 消息提示粒度是"某应用在请求注意"，不是未读计数；图标清退规则对齐 Dock 橙色标记（窗口被激活或关闭后清除）。不使用 `UserNotificationListener` 读取系统通知。
- 音量、网络、电量、输入法为纯只读展示，不提供任何调节控件或弹层；音量/WiFi 调节属于"控制中心"边界，另行决策。
- 时钟与 Windows 任务栏托盘时钟并存显示，属于接受的重复（产品边界禁止修改任务栏内容）。

## 5. 交互

- 模块点击五种去向：待办概要弹出待办信息栏（条目点击切换完成状态；跨进程点击收起由条自身的轮询补足）；消息提示聚焦该应用；性能启动任务管理器并停留“性能”页；电量/网络/音量程序化调用托盘图标唤起系统快速设置弹层（与托盘点开同一表面——不用 Win+A，新版本 build 上它打开的是整个设置应用）；输入法仍深链到设置；时钟弹出条自己的日历信息栏。天气为纯展示元素。顶栏只做跳转，不在栏内承载任何系统控件。现有深链按窗口实例选中（`ShowWidgetSettings(WidgetWindowBase)`），内部已支持按 Kind 刷新（`RefreshComponentList`）；顶栏目标组件可能已隐藏、无窗口实例，**需公开按 Kind 选中入口**。信息栏打开期间视为交互活动，智能隐藏不收回横条。
- 整条栏右键菜单沿用组件模板：进入冰蓝桌面设置 / 退出；顶栏不是可删除组件，不提供"删除"项。
- 悬停高亮：可点击模块有轻微悬停高亮。
- 交互热区 ≥ 32×32 DIP（输入法指示器最窄，用内边距补足）。
- 键盘与辅助功能：模块以无边框按钮实现，获得 UIA 名称与角色，支持 Tab/Shift+Tab 焦点顺序；进入 UI 烟雾测试的 UIA 与 Tab 验证范围。

## 6. 设置与持久化

设置中心新增"顶端信息条"页（与"Dock"页平级）：

- 显示顶端信息条（总开关，默认**关闭**；关闭时其余设置置灰保留，对齐 Dock 开关行为）；
- 显示方式：始终显示并预留顶边空间（默认）/ 智能隐藏；
- 显示器选择：与 Dock 同款显示选择器（默认主屏）；
- 九个模块独立开关（默认全开）；
- 外观：默认跟随"外观"页，可自定义。

持久化与主题包：

- Schema 升至 v27（当前 v26），新增顶栏设置节点：总开关、显示方式、显示器标识、九个模块开关、外观模式（跟随/自定义及自定义值）。显示器标识按现有显示器排列键结构存储，为未来"多显示器都显示"预留字段形态（当前只存单个）。
- v26 → v27 迁移：老状态默认顶栏关闭，不改变任何现有字段。
- 主题包归属（沿 `ThemeBindings` 已收 Dock 开关/显示方式的先例）：顶栏的**可分享字段**进入主题包——总开关、显示方式、九模块开关、外观模式与自定义值；**显示器标识不进主题包**（机器相关数据，对齐 Dock 不导出显示器设置的现状）。
- 顶栏不进入"桌面组件"组件列表（不可拖动、无逐卡锁定，由独立设置页管理）。

## 7. 预设编排

项目存在两套独立体系，顶栏只进**桌面模式**体系：

**桌面模式**（Windows 原生 / 冰蓝混合 / 苹果式，`DesktopModeRules.Apply` 写安全默认值）：

- Windows 原生：顶栏关 + 时间/天气/性能卡可见（沿用 dock 关 + 任务栏默认）；
- 冰蓝混合：顶栏关 + 三卡可见（沿用 dock 开 + 任务栏透明/模糊）；
- 苹果式：**顶栏开 + 时间/天气/性能三卡关** + Dock 开 + 任务栏智能隐藏（任务栏语义沿用既有定义不变）；
- `Apply` 的写入范围需扩展至顶栏开关与三卡可见性（三卡可见性 = `DesktopComponentState.IsVisible` 按 Kind，已存在）；接缝（扩展签名或在编排层调用）由实现计划决定。
- 模式回显 `Detect` 保持现有 `(dock, taskbar)` 二元组判定不变，**顶栏不参与回显**：在任一模式下单独开/关顶栏属于模式漂移，语义与今天单独改任务栏模式一致（回显漂移或显示为自定义）。
- 用户切换模式后仍可在各自页面单独调整（含重新打开三卡）；模式对三卡可见性的写入与 Dock 开关同级——是模块编排，不是卡片位置的越权。

**布局预设**（静谧信息层 / 冰川工作台 / 通透苹果桌面 / 居中时钟，`ApplyLayoutPreset`）：

- 保持"只改变卡片位置"的既有语义，**四种布局预设均不触碰顶栏开关与卡片可见性**，包括"通透苹果桌面"——它是卡片布局编排，顶栏的编排入口是桌面模式"苹果式"。首次引导与"布局"页的文案应让这两个入口的区别可被普通用户理解。

老用户升级后顶栏默认关闭、无任何模式写入发生，桌面维持现状（现状回归）。

## 8. 实施边界

**复用（不新写机制）**：

- AppBar 预留/释放：泛化 Dock 底边预留控制器（`DockAppBarController` 当前 `Edge` 为常量、Position 写死贴底，几何层已支持四边）——是**参数化改造**，非零成本搬用；顶部 AppBar 基础行为已有 DockSpike 顶边实测，但冲突场景（任务栏自动隐藏、第三方 AppBar 同边）无 spike 证据，依赖正式 QA；
- 智能隐藏状态机（`DockAutoHideState`）、真全屏判定（`DockVacateRules`）、Explorer 重启恢复（`TaskbarCreated` → 控制器恢复路径）、显示器回落规则：对齐 Dock 既有实现；
- 消息闪烁信号：`DockAttention` 的记录/清退语义；信号源为 Shell 钩子，**当前注册在 Dock 窗口 HWND 上——顶栏需独立于 Dock 开关获得信号**（共享宿主注册或顶栏自注册，实施计划定）；
- 时间/天气/性能：既有共享服务与快照回调；
- 设置深链（需公开按 Kind 入口）、外观令牌与 `FollowCardLook` 自定义外观、Schema 迁移框架（逐版本 if 链）、显示桌面守护、`TaskbarEdgeGuard` 顶边支持。

**新增**：

- `BingLan.App`：顶栏窗口宿主（满宽贴边 WPF 窗口、逐像素透明）、顶边 AppBar 控制路径、顶边唤出区几何（`DockRevealRules` 的顶边镜像分支）；
- 四个只读系统服务：电量（`GetSystemPowerStatus` P/Invoke）、音量（`IAudioEndpointVolume` COM，仓库已有 `[ComImport]` 先例）、网络（`NetworkInterface` + `NetworkChange`，BCL 已有使用先例）、输入法（前台跟踪 + `GetKeyboardLayout`）；
- `BingLan.Core`：待办概要聚合、顶栏设置模型与持久化、消息注意的有序跟踪、九模块视图模型（可测逻辑在 Core，Win32/P/Invoke/COM 留在 App，沿 AGENTS §4 分层）；
- Windows API 封装集中在 `App/Interop/` 既有 static class 惯例（`DockNativeMethods` 等），不散落。

## 9. 实施顺序与验收门

1. **骨架门**：顶栏窗口 + 顶边 AppBar 预留/释放 + 智能隐藏（先只有时钟模块）。验收：编译与既有测试全绿；预留模式下最大化窗口正确下移、关闭/退出/强制结束后工作区恢复；真全屏退避；Explorer 重启恢复。
2. **设置与持久化门**："顶端信息条"设置页 + Schema v27 + 迁移 + 主题包字段。验收：默认关闭 = 现状的回归用例存在且通过；设置往返、迁移与主题包导出/导入进核心烟雾测试。

## 10. 真机 QA 矩阵

记录于 `docs/TOPBAR-QA.md`（Windows 11 Build 26200，含显示器与缩放条件，对齐 AGENTS §11 对 Dock/任务栏类集成的手工记录要求）：

- 预留开启/关闭：最大化窗口工作区变化与恢复，覆盖 Win32 / UWP / Electron 常见应用；
- 顶栏与 Dock 同时开启（顶边 + 底边双预留）；
- 原生任务栏底部自动隐藏共存；
- 真全屏视频/游戏：两种模式下顶栏与唤出区都隐藏；
- Win+D / 最小化所有窗口：顶栏保持可见；
- Explorer 重启：预留与显示恢复；
- 所选显示器断开与恢复：回落主屏、恢复原位；
- 125% / 150% 缩放；
- 智能隐藏唤出/收回/延迟；
- 应用退出与进程强杀后的预留释放；
- 顶边被系统任务栏占用（Windows 10 任务栏移顶部）的回退路径：首版以单元/代码级验证覆盖，真机验证随仓库既有的 Windows 10 整体支持计划推迟。
