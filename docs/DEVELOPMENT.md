# 开发说明

面向 Windows 11 的轻量桌面伴侣：用一套冰蓝设计语言统一桌面信息、应用 Dock、安全文件收纳盒和原生任务栏外观。安装包最低允许 Windows 10 2004（Build 19041）：任务栏外观在 Windows 10 与 Windows 11 上均可选（Windows 10 的自动隐藏、模糊、透明尚未经真机验证），透明的 XAML 组件按已验证 Build 门控，设置窗口 Mica 按 Build 22621 门控，图标字体回退到 Segoe MDL2 Assets；Windows 10 尚未真机验证。

本文记录技术方案、当前实现、构建与测试。面向普通用户的说明见[使用说明](USER-GUIDE.md)。

今日列表是周历当天格的投影：`BelongsToTodayList` 接受 `Date == DateTime.Today`（独立倒数日、设有截止日期的未完成待办、右键勾选“跨天常驻”的未完成待办 `TodoItemState.IsPersistent`，以及待办卡片开启“未完成待办跨天保留” `TodoWidgetState.CarryOverIncomplete` 后 `Date <= today` 的未完成待办均跨日保留；未来日期安排与行程不顺延，勾选完成后回到所属日期），列表新增立即写入当天日期，顶栏计数、顶栏待办浮层、折叠摘要与清理范围沿用同一口径。旧无日期任务在 `LocalStateStore.Load` 时按 `CreatedDate`、`CompletedDate`、迁移当天的顺序回填日期并立即保存，保留原任务、完成状态和时间戳。`TodoService.NormalizeTodayCompletionOrder` 在恢复、切回列表、今日新增和跨天时把当天未完成项排在已完成项前，其他日期任务仍留原日历日期；WPF 以 `ObservableCollection` 的增删与 `Move` 同步已渲染的列表和周历格。午夜计时器及窗口重新激活会刷新列表、周历和摘要。行程条目由 `TodoItemState.Kind = Event` 与可空 `Time`（`TimeOnly`）表示：`TodoService.SetCompleted` 对行程不生效，`SetKind` 转为行程时清除完成状态；`OrderCompletedWithinScope` 在完成分组内把行程排在待办前，有时间的按时间升序、无时间的保持手动顺序；上移/下移、拖动调序、移到其他日期和整日编辑保存后由 `TodoService.PlaceEventsFirst` 立即恢复该日行程在前；顶栏未完成计数只统计待办，顶栏待办浮层中的行程只显示不响应点击。旧数据缺少这两个字段时按无时间待办加载。待办截止日期与可选分钟时间由 `DeadlineDate`、`DeadlineTime` 保存，独立于日历日期 `Date`；`SetDeadline` 可清除待办截止时间，独立倒数日必须有目标日期且日历位置跟随目标日期。`CountdownLabel` 对未完成待办与倒数日计算剩余时间，完成待办不显示倒计时；仅日期按天计算，指定时间按本机墙上时钟计算天、小时、分钟。今日列表持续包含有截止日期的未完成待办及独立倒数日；完成的待办保留在原日历日期。列表、周历和详情浮层把倒计时放在事项下方；日期选择与可选时间在确认后保存，取消不改变条目。卡片复用日期刷新计时器按分钟更新可见标签；顶栏浮层复用共享采样刷新绑定。Schema v40 的倒数日将原 `Date` 迁入 `DeadlineDate`，v39 待办与行程保持原有字段。待办可关联本机文件或文件夹：从资源管理器拖到待办行（行级 `PreviewDrop` 接管，路径不落入文本框）或右键“关联文件…”多选；关联在条目下方以文件名标签显示（悬停看完整路径），点击经 `ShellLauncher` 后台用系统默认方式打开（打开失败保持安静且关联不丢），标签“✕”移除单个关联；`TodoService.AddLinkedPaths` 忽略大小写去重、丢弃空值/非法字符/解析失败的路径，每条上限 16 个，只记录路径不移动文件，路径不出现在主题包。截止进入临期窗口的未完成待办（`IsDueSoon`：带时间截止 24 小时内、仅日期截止自前一天起，过期仍算；行程、倒数日与已完成不算）在今日列表以 `TodoDueSoonBrush`（强调色 15% 透明度，随主题与高对比度切换）淡染行底，排列升为“行程 → 临期待办（约截止近的在前）→ 倒数日 → 其余”，分钟计时器在临期集合变化时重排并保存，完成或改远截止后自动恢复；Schema v44 为每条事项补空的关联路径列表。

四类能力使用各自适合的产品结构：时间/天气/性能采用低干扰信息层，待办采用 Reminders 风格内容卡，文件收纳盒负责安全路径映射与整理，冰蓝 Dock 负责应用启动、窗口切换和调用 Windows 原生开始菜单，原生任务栏适配只负责透明/模糊和智能隐藏。统一的是冰蓝材质、字体、颜色、间距、动效、逐卡拖动/锁定规则和 App 设置入口，不是同一种卡片底座。职责边界与实施顺序见 [桌面表面、冰蓝 Dock 与原生任务栏设计决策](DESKTOP-SHELL-AND-SURFACES.md)。

## 技术方案

- **.NET 10 LTS + WPF（`net10.0-windows`）**：WPF 继续使用软件渲染；Windows 11 上 Dock 和隐藏把手的实时毛玻璃由自有原生 C++/WinRT 组件 `BingLan.Composition.dll`（约 150 KB）调用系统 Windows Composition 合成层绘制，托盘图标与选色器使用原生 Win32 `Shell_NotifyIconW` 和 `ChooseColorW`。玻璃使用独立的无重定向位图窗口，跟随内容窗口的位置、尺寸、显隐和层级；智能隐藏期间隐藏并复用合成背板，DPI、显示器、DWM 变化或休眠唤醒时重建；形变只改变合成几何，不逐帧缩放原生窗口。高对比度、透明效果关闭、笔记本省电模式、关闭“Dock 实时毛玻璃”、Windows 10 或初始化失败时恢复半透明背景；关机或会话结束时跳过可能触发 `CoreUIComponents 0xC0000602` 的原生 `Compositor.Close()` 销毁调用，未处理异常统一前置记录到本机 `%LOCALAPPDATA%\BingLanWidgets\crash.log`（不上传）。成本见 [安装包](INSTALLER.md)。
- **开机启动顺序**：桌面卡片按保存的可见性恢复，支持只开启顶栏或 Dock 的布局。开机后 3 分钟内启动时，后台以 250 ms 间隔探测资源管理器桌面图标视图与任务栏窗口就绪后（开机前 60 秒内额外留 1.5 秒稳定窗口），立即接管或恢复桌面图标、应用 Dock 和任务栏外观。开启“隐藏 Windows 桌面图标”（内部称清爽桌面）且登录自启有效（含检查系统“启动应用”未禁用）时，关机或注销在收到会话结束确认（`WM_ENDSESSION`，用户取消关机时不拆解外壳适配）后保持图标隐藏与有效检查点，下次登录直接接管（接管失败则回退恢复并提示）。各步骤记录本机版本与时间到 `startup.log`，不上传。
- **日常保存与界面刷新**　连续编辑在 350 毫秒后合并保存。界面线程完成状态快照，后台按顺序写盘。立即保存与退出会等待落盘。Dock 悬停在一帧内采用最后一次指针位置，聊天提醒只更新受影响的按钮。文件盒移除映射后可回收对应图标。
- **界面卡顿记录**：后台监测线程每 500 ms 探测一次界面线程（默认不订阅高频 `Dispatcher.Hooks.OperationStarted`，可通过环境变量 `BINGLAN_DIAG_HOOKS=1` 开启细粒度操作追踪），超过 2 秒未响应时在本机 `stall.log`（带构建版本号，超过 256 KB 重新开始）写入当时正在执行的界面任务、进程 CPU 占用、前台程序的进程名与窗口类名（不含窗口标题），以及窗口事件、Dock 刷新、AppBar 位置通知、玻璃背景同步、任务栏与桌面事件的近期计数，恢复后再记一行卡住时长；命名界面慢段超过 150 毫秒或上述事件 10 秒内超过 3000 次时记录诊断，每分钟至多一次。不上传（`UiDiagnostics`）。
- **单实例生命周期**：正式模式和隔离交互测试模式分别使用当前 Windows 会话内的单实例门禁；重复启动会立即退出，不会重复创建组件、托盘或并发写入同一状态文件，原实例退出或异常终止后可再次启动。带 `--replace` 启动时，先通过会话内的命名事件（实例名加 `.Exit`）请运行中的实例按托盘“退出”的路径保存并退出，再在 15 秒内接替运行；用于切换预览版本，无需手动退出或结束进程。
- **高对比度回退**：Windows 对比度主题开启时，正式组件、设置中心和外观面板会立即改用不透明系统色；关闭后恢复用户原有的冰蓝材质与自定义颜色。
- **桌面组件窗口**：每个组件都是 WPF 逐像素透明的无边框工具窗口；卡片继续使用圆角 Clip 内的半透明冰蓝材质；Dock 和把手使用原生合成毛玻璃与几何圆角裁剪，不使用 WCA。组件固定在桌面层：点击、编辑或拖动组件时仍可接收输入，但窗口始终排在所有普通窗口下方（拦截 `WM_WINDOWPOSCHANGING` 把 Z 序改为最底，首次创建与重新显示时亦落回 `HWND_BOTTOM`），组件打开的对话框照常显示在前面；普通应用窗口会自然覆盖组件，不修改 Explorer、任务栏或系统设置。“显示桌面”（Win+D）由两层机制保证组件与桌面栏保留：其一，Shell 若把卡片、顶端信息条或 Dock/把手隐藏或最小化（不同 Windows 版本对工具窗口的处理不同），窗口会在下一条消息内用 `SW_SHOWNOACTIVATE` 自行恢复显示、回到原位，不抢前台焦点（状态读自原生窗口，因为 WPF 察觉不到其他进程对可见性的修改）；其二，Windows 10/11 的“显示桌面”会把桌面表面（置顶或承载 `SHELLDLL_DefView` 的 `WorkerW` / `Progman`，含 Windows 11 24H2+ 不带 `WS_EX_TOPMOST` 的 DWM 桌面抬升）抬高并盖住下方窗口——`DesktopSurfaceWatcher` 监听前台、顶层窗口显隐、最小化、恢复、虚拟桌面与重排事件。检测到桌面露出后立即提升组件。检查前台普通应用时直接读取其原生窗口，后台普通窗口则只枚举到桌面表面，并过滤辅助窗口。普通窗口开始恢复或取得前台后立即回落组件，启动较慢的应用由限时复查处理。“显示桌面”期间，卡片与分组盒放在桌面表面上方，沿用桌面表面所属的窗口层级。桌面表面处于普通层时，应用重新激活后由 Windows 自然排到组件前方。桌面表面处于置顶层时，组件放在该表面上方并优先排在任务栏下方。顶端信息条与 Dock/把手同步恢复各自的层级。回落时，卡片与分组盒作为一批移至 `HWND_BOTTOM`。托盘“隐藏桌面组件”和组件可见性设置走 `HideFromApp`，不会被恢复。
- **内容与设置分离**：普通桌面状态只显示标题、数据、待办、文件入口和直接内容动作；单击选中卡片时只临时显示一个统一设置入口。所有卡片及其显示、锁定、颜色、圆角、尺寸和内容配置集中在冰蓝桌面 App 的“桌面卡片”页，以左侧组件列表和右侧详情呈现。
- **冰蓝材质个性化**：主体、文字、圆角、字号和信息密度按组件独立保存，并从统一设置中心调整。文字颜色提供白色、黑色快捷项和自定义值；不存在的本机字体会回退到可用字体。材质是共享设计令牌，但信息层、待办、分组盒和 Dock 不强制使用同一种容器骨架。
- **单一可调圆角**：关闭 DWM 非客户区边框与第二层系统圆角，使用唯一的 WPF `RectangleGeometry` 同时裁剪标题、主体和所有内容；不再使用会产生二值硬边的 HWND Region。卡片外框默认 `12 DIP`（可在设置中调节 `0–32 DIP`），内部列表项与卡片默认 `8 DIP`，轻量控件与小标签默认 `6 DIP`；非无底板模式下卡片外沿绘制 `1px` 顶光质感边框（高对比度主题使用系统文本色）。
- **逐卡拖动与锁定**：卡片默认可直接从标题或非交互空白区域拖动；复选框、文本输入、删除和新增等内容控件不会被当成拖动区域。每张卡片可在“桌面卡片”页单独锁定，锁定后内容仍可操作；拖动卡片边缘或四角可调整大小，也可在对应组件详情中输入精确尺寸。双击待办、便签或分组盒的标题、在卡片右键菜单点击“重命名”或按 F2 可修改标题，Enter 确认，Esc 放弃（在文件收纳盒中选中单个项目按 F2 则打开“修改显示名称…”）。待办、便签和分组盒使用并入卡片本体的 48 DIP 标题行（左侧 `4×16` 标题色标默认 `#5B9BD5`、底部 `1px` 分隔线，折叠后卡高收为 `48 DIP`，并在标题右侧仅显示数量摘要：待办在有未完成项或空列表时显示当前视图下的 `N 项未完成`、已有待办且全部完成时显示 `已全部完成`，分组盒显示 `N ## 运行

冰蓝总览卡按需建立 WPF 窗口与搜索会话，可使用 Dock 入口、托盘菜单、顶端信息条居中搜索按钮或全局热键（默认 `Ctrl+Alt+F`）切换并聚焦搜索框；内部承载桌面/开始菜单快捷方式解析、`TopBarSearchRules` 排序与拼音首字母匹配（多音字取常见读音、无正常结果时短前缀容错）、Windows 索引与可选本机 Everything 客户端（开关读取 `LauncherPreferences.UseEverything`）。开始菜单目录与图标改为首次打开总览卡时按需加载（启动空闲阶段不再提前扫描开始菜单或预热首屏图标）；开始菜单缓存过期时先返回已有列表并在后台刷新（不再清空已有图标缓存）。结果网格按视口创建和回收控件，图标使用进程级缓存 `LauncherIconCache`（支持同键并发合并、LRU 上限 256 与 5 分钟闲置过期驱逐）在后台 4 路并行按首屏与可见范围加载并优先使用快捷方式自身图标。应用入口按 `LauncherIdentityRules` 统一合并（同可执行文件在剥离无害来源参数后相同，或同文件同名且至少一方无有效参数；保留不同非空参数变体，同一文件夹下 3 项及以上带参数变体收拢至「辅助入口」），Windows 索引与 Everything 返回的快捷方式先解析目标再合并并过滤卸载项与开始菜单分组文件夹；常用星标支持本机偏好切换（跟随 Dock 固定 / 总览卡独立收藏 / 关闭），右键可直接固定或从 Dock 取消固定，发送到桌面分组盒复用文件映射。总览卡继续保持与整体卡片一致的浅色冰蓝玻璃风格（仅当桌面整体为深色玻璃时切入深色模式），磨砂模式按 `LauncherReadabilityRules` 计算的真实不透明度渲染（不再叠加 Dock 的 `0.24` 衰减系数）以保证背后为深色窗口时仍明亮可读；清透模式取消逐项文字底纹块，保持轻透浅冰蓝玻璃，文字跟随全局 `Style.TextInk` 并配合柔和对比阴影分离（白字配暗阴影、深字配浅白光晕），与文件盒视觉语言统一；设置页额外提供「总览卡背景方式」本机偏好，支持「直接浮在当前窗口上（默认）」（原“实时透视”）、「用桌面壁纸作底」（原“静态壁纸底衬”，读取当前系统壁纸按面板坐标裁切渲染，不收起窗口）、「先切回桌面（适合动态壁纸）」（原“弹出时切到桌面”，打开时异步最小化其他普通窗口以呈现动态壁纸，取消关闭时还原）三种模式；应用界面字体使用系统自带的 `Segoe UI Variable Text`（Windows 10 回退 `Segoe UI`），中文由 `Microsoft YaHei UI` 兜底，不再随包携带界面字体；旧数据或导入主题里指定的 `Google Sans` 自动映射为 `Segoe UI Variable Text`。任务栏按显示器确认边位并使用工作区避让。各入口与验收场景见 [冰蓝总览卡与任务栏边位](LAUNCHER-AND-TOPBAR-DESIGN.md)。

冰蓝总览卡顶部在浏览态显示「应用」「文件」「我的分组」（`Ctrl+1/2/3`），进入搜索态后左侧展开搜索专用的「全部」入口，支持点击顶栏四个标签或按 `Ctrl+Tab` 筛选结果而不清空 `SearchBox`，底栏把「仅搜当前范围」（含当前分组、应用分类与已打开的文件夹目录）置于来源筛选 `SourceFilter` 旁；清零搜索框隐藏「全部」并恢复浏览前的标签、分类与滚动位置。文件页支持可点击分段面包屑、`Backspace` / `Alt+Left` / 鼠标侧键返回上级、按名称/最近修改排序、列表视图修改时间与文件大小显示、悬停快捷操作（打开位置/复制路径/加入分组）以及只读 `FileDrop` 拖出到其他应用。左侧导航与标题/底栏去除重复计数摘要；浏览模式初始不默认选中结果项（`SelectedItem == null` 且键盘焦点框标示关闭），`Left`/`Right` 仅焦点在 `ResultsList` 内或 `SearchBox` 为空时移动网格选择，`Up`/`Down`/`PageUp`/`PageDown` 仅焦点在 `SearchBox` 或 `ResultsList` 内有效，并支持 `Home`/`End` 跳至首末项，避免切换顶部控件焦点或编辑关键词时方向键误抢操作；搜索态仍默认选中首项。自建分组继续保存应用、文件和文件夹的多组关联，并支持经 `LauncherGroupRules.TryRename` / `TryDelete` 校验的内联重命名与内联二次确认删除（入口位于分组页头部按钮与左侧分组导航右键菜单，不影响原文件）。

Dock 左侧的功能组有 Windows 开始菜单、冰蓝总览卡和显示桌面。三项可见性保存在本地 `DockState`，状态 Schema v50 增加冰蓝总览卡开关，旧配置默认显示该入口。冰蓝总览卡外观和 Dock 功能入口开关均为本机设置。

状态 Schema v51 保存冰蓝总览卡的 `LauncherGroups` 和 `LauncherAppearance` 材质选择。旧配置从空的自建分组和磨砂材质开始。分组引用及文件路径保存在本机。

状态 Schema v52 增加本机的 `LauncherAppCategoryOverrides`，保存用户指定的应用类别。旧配置迁移为空的类别覆盖表，现有分组和外观保留。

状态 Schema v53 保存本机的 `LauncherEnabled`。旧配置默认开启。关闭时收起现有面板，隐藏 Dock、托盘和顶端信息条的入口并注销全局搜索热键。Dock 与顶栏开关的原始偏好独立保存。

状态 Schema v54 增加本机的 `LauncherPreferences`（保存上次停留主标签、是否显示最近使用文件、应用按名称排序及文件/分组列表视图偏好，不进入主题包），并将 v52–v53 的旧分类覆盖值（原「网盘与传输」→「系统与工具」，原「地图与工程」→「其他」）向前迁移。

状态 Schema v55 将搜索入口与结果呈现统一收口到冰蓝总览卡：删除独立搜索窗 `SearchWindow`、`SearchPresentation` 及 8 个已退役的 `TopBarState` 搜索外观/布局/来源字段，在 `LauncherPreferencesState` 增加 `UseEverything` 开关；v54 及更早配置升级时自动把原 `TopBar.ExtensionData["UseEverything"]` 迁入 `LauncherPreferences.UseEverything`，清除 `TopBar.ExtensionData` 中 8 个退役键，同时保留 `SearchHotkey` 与 `Modules.Search`。

状态 Schema v56 引入独立全局快捷键模型 `GlobalHotkeysState`（本机保存，不进入主题包）并由常驻消息窗口 `GlobalHotkeyHost` 统一注册，解除总览卡快捷键对顶端信息条的绑定：v55 及更早配置升级时自动把原 `TopBar.SearchHotkey` 迁入 `Hotkeys.Launcher`，并默认启用 `Hotkeys.PeekFileBoxes`（`Ctrl+Alt+Space`，可清空停用），另在「设置 → 通用设置 → 快捷键」提供打开常用文件夹（`GlobalHotkeyKind.LauncherFiles = 5`，默认留空、不进主题包、不改 Schema；触发时直达总览卡「文件」页常用位置且不改写 `LastTab`，面板已开在其他页时切至常用位置、已在常用位置时再按收起）、隐藏/显示全部桌面组件、快速新建待办、清爽桌面临时切回原生桌面图标四项按需录制快捷键（全屏游戏/视频下自动跳过，录制探测经 `GlobalHotkeyHost.Probe` 返回 `GlobalHotkeyProbeResult` 区分“已被冰蓝的‘xxx’使用”与“已被其他程序占用”，并支持清空）。文件收纳盒新增「临时浮起文件收纳盒」（原“临时速览”，`DesktopPeekController`：带遮罩临时抬起文件收纳盒，拖出文件时遮罩立即撤下并在松手后自动回落桌面层，Esc/失焦/点击空白处退出）、收起态拖入外部文件悬停 220 ms 自动临时展开（放下或移出后恢复收起）、自动收起模式下的标题栏临时固定展开图钉（`FileBoxAutoCollapseRules` 增加 `isPinnedOpen` 门控）与被动 QuickLook 空格预览（`QuickPreviewLauncher` 仅在 QuickLook 已运行时走文档化命名管道，不捆绑也不自启）。冰蓝总览卡新增右上角「固定并置顶」图钉（开启后临时置顶且切到其他窗口或打开项目不自动收起，支持拖动空白处移动位置与双击归位，取消或关闭即恢复普通层级）、`LauncherPreferences.PinnedFolders` 自定义收藏常用文件夹（上限 16，支持右键固定/取消与面板内只读展开）、`LauncherPreferences.OpenCounts` 本机打开频次加权排序（上限 200，不进主题包）、拖出文件期间窗口临时隐形并置 `WS_EX_TRANSPARENT` 避免遮挡目标软件、`Ctrl+C` 复制文件及空格 QuickLook 预览。

首次运行会显示首次引导、桌面信息、一个待办便签和一个文件收纳盒，并在通知区域显示托盘图标。双击托盘图标会打开冰蓝桌面设置，窗口已最小化时会恢复到前台；重复启动不会创建第二套窗口或托盘。

从托盘或组件右键菜单选择“在冰蓝桌面中设置…”，也可单击卡片（或用 Tab 键把焦点移入卡片）后点击出现的设置按钮；同一个设置窗口会打开“桌面卡片”页并直接选中当前卡片。左侧切换组件，右侧修改该卡片的显示、锁定、外观、尺寸和专属内容设置。只有主动搜索天气城市时才发送输入的关键词；不会使用 IP、GPS、Wi-Fi 或设备位置。

- 分组盒底部“自动整理”会把当前用户桌面和公共桌面的直接子项放进各分组盒：在“桌面卡片”页选中某个分组盒，可勾选它收纳的类型（文件夹、软件与快捷方式、文档、图片、视频、音乐、压缩包）或填写其他扩展名；没有盒子收纳的项目归入“软件与快捷入口”“桌面文件夹”“桌面文件”三个盒子。重复执行只补新增映射，并清除已确认原路径不存在且父目录可读取的映射；“桌面卡片”页分组盒详情里的“分组盒自动刷新”开关（对所有分组盒生效）（默认关闭）开启后，分组盒监听映射所在目录与桌面目录：原文件被删除后确认已删除的映射自动移除，桌面上新出现的项目自动收纳进已有分组盒（不新建分类盒；下载中的临时文件按扩展名跳过，改名完成后才入盒），保留其他盒中已有的映射。用户手动移除或转出的路径记入源盒的自动收纳排除记录，拖回或主动导入可恢复。自动刷新提交前重新校验当前盒和映射。原文件及路径保持原样。
- 未锁定卡片可直接拖动标题或非交互空白区域；要避免误拖时，在“桌面卡片”页选中该卡片并开启“锁定卡片位置”。
- **卡片宽高在对应组件详情中输入**：待办支持今日列表与周历视图（`WeeklyView`，设置中心“桌面卡片”页与卡片周历工具栏均可随时切换 `WeeklyWeekCount` 1–5 周（默认 4 周）以及每周起始日 `WeekStartsOnSunday`（周一开头 / 周日开头，Schema v62，默认周一开头）；每行连续排列 7 天，跨月不断行，每月 1 日标出月份，内置 `ChineseLunisolarCalendar` 农历显示，1 周模式锚定本周、2–5 周模式含上一周起始日）；列表视图仅展示周历今天格的任务（顶栏待办计数同口径），跨天后旧任务仍留在原日期供重新安排；文字始终可直接编辑，Enter 提交，Esc 放弃本次修改；空白行显示“输入待办…”提示，底部统计只计算写了内容的待办；“清理已完成”仅清理今日已完成项，保留其他日期历史，“隐藏已完成/显示已完成”同步过滤列表行、周历格内预览、“+N”溢出计数与详情浮层；周历格列出当天全部待办，滚轮可在格内滚动，日期行右侧的“+N”只计当前格子放不下的条目（随卡片尺寸和字号缩放实时计算），格子高度放不下一条两行待办时每条改为单行省略显示，格内不放删除按钮（右键菜单或详情浮层删除）；周历格单击选中、点“+N”或标题栏 `+` 弹出当日详情浮层 `DayPeek`（支持前一日/后一日切换、底部回车新增、双击行内编辑、指针悬停 300 ms 抬起后拖拽调序、右键移到明天/后天/大后天及单步撤销 Toast），双击格子打开无边框 `DayEditWindow` 多行序号文本编辑（未改动行按文本优先对齐作位置锚点，锚点区间内未认领条目按原位改字复用并保留 `Id`、完成状态与完成时间戳，区间外新增行创建为未完成新条目）。

- 文件、文件夹、快捷方式或 URL 拖进桌面分组盒只记录路径；自动显示名隐藏快捷方式和程序后缀（.lnk、.exe 等，文档后缀保留，悬停可见完整路径），双击打开，右键可调整手动顺序、修改显示名称（不重命名原文件）、转移到其他分组盒或移除映射；原路径不存在时会标记为“已失效”，确认原路径不存在且父目录可读取时才清除映射，磁盘未连接、网络共享离线或访问被拒绝时保留映射，右键可重新定位到新路径或移除。分组盒详情里的“允许从分组盒删除原文件”（对所有分组盒生效）（默认关闭，本机设置，不进入主题包）开启后，右键菜单在“移除映射”下方单独出现“删除到回收站…”，选中项目按 Delete 键走同一流程：先按 `OriginalFileDeleteRules` 拒绝系统入口、已失效项、磁盘根目录、系统与用户文件夹及其上级，以及不在本地固定磁盘上的位置（U 盘、网络盘、UNC 路径通常无法回收，直接拒绝而不提供永久删除）；确认后在后台 STA 线程调用 `SHFileOperation`（允许撤销、要求永久删除前警告），原文件确实移走后才移除映射，取消或失败时保留映射并在盒内提示。未开启时 Delete 键不做任何事，“移除映射”的含义不变。
- 分组盒内支持多选：Ctrl+点击切换加选，Shift+点击从上次点击处范围选择，无修饰点击只高亮单击项，点击空白处或按 Esc 清空；选中为瞬态高亮，不持久化，失效清扫、排序或视图切换重建列表后按映射 Id 恢复。选中两项及以上后右键出现批量菜单：批量移除映射、转移到其他分组盒（目标盒已有同路径项时跳过并提示）、在开启“允许从分组盒删除原文件”时按一次汇总确认批量删除到回收站（系统入口与已失效项不计入、逐项套用与单项相同的拒绝规则，任何一项取消即停止后续项），焦点在选中项上按 Delete 走同一批量流程；多选拖出（如拖到 Dock 固定）携带全部可拖选中项的路径，允许的拖放效果为复制与链接（不提供移动），拖到文件夹或聊天窗口得到副本；把单项或多选项目直接拖到另一个冰蓝文件收纳盒中可直接转移映射（按住 Ctrl 拖放改为复制映射、源盒保留），均不触碰磁盘原文件；右键“复制”与 Ctrl+C 以文件列表加首选效果“复制”放入剪贴板，粘贴得到副本，在目标分组盒中按 Ctrl+V 可把剪贴板中的文件/文件夹路径直接粘贴为映射，原文件不被移动或修改。图标瓦片网格收紧为 `MinTileWidth = 66`、单元高 `82 DIP`（保留 43 DIP 图标）、列表行高 `28 DIP`。批量操作与单项操作同一套 `FileMappingService` API 循环完成，不触碰原文件的边界不变。
- 点击分组盒标题栏的“+”会打开添加菜单，可选择文件、文件夹，一次导入当前用户桌面与公共桌面的第一层项目，或添加此电脑、回收站、下载、桌面等系统入口；标题栏排序菜单提供手动调整、按名称、按类型和按修改时间（新的在前，失效项排在末尾）四种方式；底部常驻“自动整理”按钮会按软件入口、文件夹和文件生成或补充分组盒。操作区会显示新增数量或没有新项目的结果；导入、整理与排序都不会移动、重命名或删除原文件。
- 托盘右键“新建文件收纳盒”按级联偏移新建空盒；“框选新建文件收纳盒…”打开覆盖整个虚拟桌面的瞬态遮罩（`BoxMarqueeOverlay`），拖出的矩形就是新盒的位置与尺寸，小于 40 DIP 视为误触取消，Esc、右键或遮罩失焦同样取消；开启网格对齐时新盒位置对齐 16 DIP 网格。遮罩是短生命周期的顶层窗口，非常驻也不监听全局输入，完成或取消后立即关闭，新建的盒子保持空列表，拖入文件或点“+”添加。
- 组件右键菜单只保留进入冰蓝桌面设置、删除组件和退出，不再复制一套桌面内设置。

搜索来源与入口：统一收口到冰蓝总览卡，默认通过系统 ADODB / Search.CollatorDSO 读取 Windows 已有索引，以 System.ItemUrl 还原真实文件路径，避免本地化显示路径导致重复结果或无法打开；先按文件名词前缀和字面量条件查询，空结果且非短 ASCII 串时回退文件名包含查询；不读取正文，不修改系统服务或索引范围，不携带额外依赖。每次最多 128 个候选，最多一个原生查询，连接和命令超时为 1 秒，旧查询取消且迟到结果不覆盖新输入。可选 Everything（`LauncherPreferences.UseEverything`，默认关闭，可在「设置 → 冰蓝总览卡」切换）可用时通过官方 Unicode WM_COPYDATA 协议查询本机运行中的完整版 Everything，不可用时自动回退 Windows 索引，两者均不可用仍保留桌面与应用基础搜索；不携带 SDK DLL、不启动 Everything、不维护索引。顶端信息条不再维护独立输入框、结果浮层或 `SearchWindow`，居中“搜索应用、文件…”按钮和全局热键（默认 `Ctrl+Alt+F`）均直接切换冰蓝总览卡并聚焦其搜索框。个人设置与热键均不进入主题包。协议按官方 SDK 文档独立实现，验证版本为 Everything 1.4.1.1032；Everything 主程序使用 MIT 许可，PCRE 等组件沿用各自许可，冰蓝不分发其程序、源码或 SDK 二进制。

图标读取由分组盒、应用选择器和搜索结果共享：优先保留真实高清帧；系统 Jumbo 图像列表仅在左上角填充旧图标时，回退到较小的系统图标帧，避免透明画布把图案缩成小点。原有居中留白保持不变，不修改快捷方式或系统图标。分组盒排序、上下移或重新定位重建列表时，缺失的图标同样在后台提取后回填，不在界面线程同步提取。WPF 回归检查覆盖 16、32、48、64、128、256 像素源图标和冻结后的跨线程使用。

桌面卡片的“稳定半透明”不会模糊壁纸。Dock 和把手在 Windows 11 透明效果开启时使用实时毛玻璃，合成层跟随原有形变动效；不支持时保留可读的半透明背景。玻璃窗口只绘制背景，不接收鼠标或键盘输入，隐藏和退出时销毁。

Dock 玻璃已在 Windows 11 Build 26200、125% 缩放下检查正式 Dock 窗口的受控条纹背景、收起把手与再次展开；自动测试覆盖背景跟随移动和尺寸、形变中不产生 WPF 尺寸消息、不自行置顶、高对比度回退和恢复、隐藏/重显与关闭清理。可用 `dotnet run --project tests/BingLan.UiSmokeTests -c Release -- --dock-glass-preview` 启动正式窗口类的独立验收场景，不读取个人配置；自动保存场景截图可再加 `--dock-glass-capture`。该入口暂停前台轮询，不能代替真实自动隐藏、全屏、Explorer 重启和多显示器/混合 DPI 的综合验收。玻璃路径的常驻 CPU、GPU、内存与其他 Windows Build 尚未完成统一实测。

外观试选的独立验收入口：`dotnet run --project tests/BingLan.UiSmokeTests -c Release -- --appearance-preview`。仅使用内存中的示例状态，不创建正式宿主或改动系统外观。加 `--appearance-capture` 会把浅色、深色、无底板、自定义文字、对比、小窗口及内容放大场景和竖屏布局图保存到 `artifacts/appearance-preview/<UTC时间>` 并退出。内容放大用于检查布局，不能替代真实混合 DPI 验证。只运行外观草稿回归检查可使用 `dotnet run --project tests/BingLan.UiSmokeTests -c Release -- --appearance-tests`，输出各阶段结果，模态阶段超时会关闭并报告失败。

另一个 WPF/Win32 项目需要修复相同问题时，可直接参考 [Metrik 双层圆角修复方案](METRIK-ROUNDED-CORNER-FIX.md)。

桌面图标/文件组合整理、Pogget 行为取舍、普通便签边界和后续交付顺序见 [桌面整理盒与便签产品定义](DESKTOP-ORGANIZER-AND-NOTES.md)。

## 冰蓝 Dock 与任务栏验证

外设电量模块默认关闭。启用并选择本机 `BatteryHub.exe` 后，信息条共享一次 `--json` 扫描，正常间隔为 60 秒。浮层沿用顶栏材质，向屏幕内侧展开，可手动刷新。程序路径仅保存在本机，模块开关与排序随主题导入导出。未配置程序时，模块浮层提供设置入口。BatteryHub 由其项目单独发行。[BatteryHub CLI 文档](https://github.com/ekmope/BatteryHub#command-line)

固定应用的运行指示结合窗口分组和当前 Windows 会话的进程。各显示器共用后台进程检查，应用退出后由现有 Dock 刷新更新指示。

「添加到 Dock」列出开始菜单应用和系统位置。应用优先显示快捷方式指定的本地图标，无法读取时依次使用程序自带图标和 Windows 提供的图标。回收站与此电脑使用 Windows 系统目标，也可从桌面直接拖入 Dock。桌面、文档、下载和图片按本机实际文件夹路径固定。系统位置沿用固定项的去重、排序和取消固定，打开后由资源管理器处理。可在「冰蓝 Dock → 尺寸与高级」开启任务视图按钮，点击调用系统 Win+Tab。同一区域可开启「显示快速设置按钮」，点击经共享的系统入口服务打开 Windows 快速设置，面板不可用时打开 Windows 设置。两个按钮默认关闭，开关和系统位置固定项保存在本机配置中。

Dock 使用「始终显示，保留底部空间」且已开启最大化时临时隐藏时，可启用「后台有最大化窗口时也收起 Dock」。复用智能隐藏的同屏窗口检查，排除最小化、隐藏和其他虚拟桌面的窗口。最后一个符合条件的窗口还原、最小化或关闭后恢复预留。两个新增开关在旧配置中默认为关闭，不进入主题包。

顶部信息条默认在屏幕顶部。在「顶部信息条 → 信息条位置」可改到底部。始终显示时由 AppBar 协调底部预留，智能隐藏时在同屏底部 Dock 与 Windows 任务栏的内侧定位。音量、网络、日历、待办等浮层和内联搜索向工作区打开。智能隐藏时，按住鼠标左键不会唤出已收起的信息条，松手后从头计算被窗口覆盖时的 350 毫秒停留。真全屏时信息条退避。

「桌面卡片 → 快捷入口」的列表可拖动排序，当前选中屏幕的顺序立即保存。文件收纳盒可选「向上展开（标题栏在底部）」。同一组合盒共享方向。贴边隐藏时沿用侧边展开，解除贴边后恢复设定方向。

Schema v68 保存信息条位置、收纳盒展开方向和逐盒自动收纳排除路径。旧配置沿用顶部、向下展开与空排除记录。三个字段均为本机设置。

Schema v69 可保存外设电量模块和本机 BatteryHub 程序路径。旧配置默认关闭外设电量；主题只携带模块外观、开关与顺序。

顶栏右侧的“托盘”按钮通过 `TrayOverflowController` 按需打开或收起 Windows 原生隐藏图标面板；Windows 11 默认显示，模块开关可关闭，Windows 10 隐藏该入口。控制器不挂常驻 Explorer 钩子，仅在面板打开期间（含唤出后 2 秒窗口识别期）以 200 ms 间隔检查面板状态，面板关闭后停止计时器；处理中的重复请求直接忽略；关闭模块与应用退出共用限时清理，不弹出模态对话框。按钮不改变自动隐藏设置，行为与 Win+B 一致：面板在系统任务栏上打开，位置由 Windows 管理，Dock 在面板处于前台时收起。个人配置 Schema v33 将已有顶栏的托盘模块初始化为开启，保留顶栏总开关及其他模块设置；模块开关随顶栏主题字段导入导出。

隔离验收入口 `--shell-surfaces-preview` 与正式入口复用控制器，附加 `--tray-corners` 检查两角唤出；`--tray-slow-uia=<毫秒>` 仅在验收时模拟调用前延迟。v0.2.52 安装版和免安装版包含顶栏托盘入口，独立工具用于兼容性验收。兼容范围、观察结果与未覆盖场景见 [顶栏与系统入口验证](TOPBAR-QA.md)。

正式 Dock 的真机结果、资源占用和已知限制见 [冰蓝 Dock 真机验证](DOCK-QA.md)；本机单屏 125% 下的点击、固定、排序、最大化、全屏、智能隐藏、Explorer 重启和强制结束恢复均已通过，多显示器与混合缩放尚未覆盖。阶段 0 隔离实验、ManagedShell 取舍和四边 AppBar 记录保留在 `design-lab/BingLan.DockSpike/README.md`。任务栏透明、模糊、自动隐藏、崩溃恢复和桌面模式的真机结果见 [Windows 任务栏适配真机验证](TASKBAR-QA.md)。清爽桌面的恢复协议与真机结果见 [清爽桌面技术设计与恢复协议](DESKTOP-CLEAN-MODE-TECHNICAL-DESIGN.md)。
