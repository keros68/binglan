# 冰蓝桌面待办与需求池（Backlog）

本文件记录用户反馈中**待进一步排查**或**改动较大 / 涉及产品边界**、暂未并入当前小版本的事项，便于后续按优先级排期。当前 MVP 基线与边界仍以 [MVP 产品设计](MVP-PRODUCT-DESIGN.md) 为准。

---

## 一、待排查问题

### 1. 启动时报 `Unknown Hard Error`
- **来源**：评论区用户反馈（丨白泽，2026-11-23）
- **现状**：历史版本已处理关机/会话结束阶段的 `CoreUIComponents 0xC0000602`；启动阶段 `Unknown Hard Error` 尚缺现场日志。
- **下一步**：收集出错用户的 Windows 版本与 Build、安装版/免安装版形态、`%LOCALAPPDATA%\BingLanWidgets\crash.log` / `startup.log` 以及 Windows 事件查看器中对应的异常模块名后定位修复。

### 2. 缩放或最小化窗口时原生自动隐藏任务栏弹出
- **来源**：用户群反馈（木木o，2026-11-24）、评论区（最小化时任务栏弹出）及 [Issue #33](https://github.com/keros68/binglan/issues/33)（v0.6.5，使用 Dock 时 Windows 任务栏偶发弹出）。
- **现状**：常显 Dock 的底边保护已在 `v0.4.4` 修复。自动隐藏任务栏支持「仅底部两角」唤出（默认）及「有新消息时不弹出任务栏」。开发代码包含针对最后一个窗口最小化时任务栏接到焦点的[恢复处理](../src/BingLan.App/Taskbar/TaskbarMinimizeFocusGuard.cs)，仍需复查反馈场景。
- **核验**：记录冰蓝版本、Windows Build、Dock 显示方式和任务栏设置（自动隐藏、触边唤出及新消息提示）。将鼠标移离触发边，分别缩放窗口、最小化普通窗口及最小化最后一个窗口。核对原生任务栏是否弹出，以及是整个 Dock 暂时让位，还是只有该应用的运行图标消失。若任务栏仍弹出，记录焦点是否落到任务栏。若仅运行图标消失，记录应用名及最小化前后的窗口识别结果。

### 3. WPS 表格底栏偶发被遮挡
- **来源**：评论区反馈，WPS 表格最下方一栏偶尔显示不全。
- **核验**：记录 WPS 与冰蓝版本、Windows Build、显示器与缩放比例、Dock 显示方式和任务栏自动隐藏设置。复现时分别检查普通窗口和最大化窗口，确认遮挡来源是冰蓝 Dock 还是 Windows 原生任务栏，并记录工作区底边与被盖住的控件。

### 4. 同一游戏多开后无法从 Dock 切换窗口
- **来源**：评论区反馈，同一游戏三开时点击 Dock 没有反应，从 Windows 任务栏可以选中窗口。
- **核验**：记录游戏名、启动方式及三个窗口的显示状态。对照 Windows 任务栏和 [Dock 右键窗口菜单](../src/BingLan.App/Windows/IceBlueDockWindow.xaml.cs)，确认三个窗口是否都被识别，再逐项检查能否还原并切到前台。记录左键点击的结果，区分窗口漏识别、激活失败和窗口选择入口不易发现。

## 二、中长期功能需求

### 5. 完整多屏 / 双屏支持
- **来源**：用户群持续反馈（Lawrence Fan 等）
- **现状**：支持物理显示器的独立桌面档案、各屏 Dock 与顶部信息条和显式离线档案关联。
- **待验证**：更多实体显示器和扩展坞组合，以及多屏工作区预留、全屏与 Explorer 重启。

### 6. 顶部信息条「上岛」（灵动岛 / 胶囊形态）
- **来源**：用户群反馈（满月居于空、财税波哥）
- **现状**：[TopBarWindow.xaml.cs](../src/BingLan.App/Windows/TopBarWindow.xaml.cs) 内已有默认关闭的实验性胶囊骨架（`_enableExperimentalCapsule`），仅做过待办概要展开验证。
- **评估**：需补齐多模块摘要、动效、避让全屏与外观适配，排在核心稳定性与多屏之后。

### 7. 微信 / 钉钉等应用气泡消息弹窗
- **来源**：用户群反馈（财税波哥、家宝·Daily）
- **现状**：目前顶栏「消息提示」与 Dock 橙点 / 红数字胶囊仅响应 `HSHELL_FLASH`，不读取系统通知中心。
- **评估**：若做气泡弹窗，需评估 Windows `UserNotificationListener` 权限要求、隐私边界（[MVP-PRODUCT-DESIGN.md](MVP-PRODUCT-DESIGN.md) 明确不采集/不托管系统通知中心）以及微信/钉钉是否向系统投递 Toast 通知的兼容性。

### 8. Dock「始终显示且不占底栏空间」悬浮模式
- **来源**：用户群反馈（面朝大海cc）
- **现状**：[DockState.cs](../src/BingLan.Core/Models/DockState.cs) 提供「始终显示并保留底部空间（可勾选最大化时让出）」与「智能隐藏」两档。
- **评估**：若新增“始终悬浮且不预留工作区”，会与最大化窗口底边状态栏/输入区发生遮挡，需先明确与 `AGENTS.md` §6“全屏或最大化应用不能被 Dock 无意遮挡”的交互取舍后再决定是否作为显式可选进阶项引入。
