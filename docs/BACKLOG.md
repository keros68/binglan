# 冰蓝桌面待办与需求池（Backlog）

本文件记录用户反馈中**待进一步排查**或**改动较大 / 涉及产品边界**、暂未并入当前小版本的事项，便于后续按优先级排期。当前 MVP 基线与边界仍以 [MVP 产品设计](MVP-PRODUCT-DESIGN.md) 为准。

---

## 一、待排查问题

### 1. 启动时报 `Unknown Hard Error`
- **来源**：评论区用户反馈（丨白泽，2026-11-23）
- **现状**：历史版本已处理关机/会话结束阶段的 `CoreUIComponents 0xC0000602`；启动阶段 `Unknown Hard Error` 尚缺现场日志。
- **下一步**：收集出错用户的 Windows 版本与 Build、安装版/免安装版形态、`%LOCALAPPDATA%\BingLanWidgets\crash.log` / `startup.log` 以及 Windows 事件查看器中对应的异常模块名后定位修复。

### 2. 缩放窗口时原生自动隐藏任务栏弹出
- **来源**：用户群反馈（木木o，2026-11-24）
- **现状**：
  - 已在 `v0.4.4` 修复常显 Dock 模式下底边挡板被 Explorer 压下去的问题；
  - 已将自动隐藏任务栏「鼠标触边唤出」默认值调整为 **仅底部两角**，减少居中 Dock 区域误触；
  - 另需用户确认已开启「有新消息时不弹出任务栏」（关闭系统 `TaskbarFlashing`）。
- **下一步**：待用户升级新版本并开启上述保护后复查；若窗口缩放或最小化最后一个窗口时仍必弹，按实机抓取的 `ForegroundWindow` 与 `Shell_TrayWnd` 焦点变化日志再评估是否做定向焦点回落桌面（`Progman`）兜底。

## 二、中长期功能需求

### 3. 完整多屏 / 双屏支持
- **来源**：用户群持续反馈（Lawrence Fan 等）
- **现状**：目前支持把单个 Dock、单个顶部信息条指定到某一块显示器，以及桌面卡片按显示器排列记忆位置；尚不支持每块显示器各自运行独立 Dock 与顶部信息条。
- **评估**：涉及多套 AppBar 预留、混合 DPI、副屏任务栏独立边缘挡板、多屏焦点与全屏判定隔离，工作量较大，作为独立里程碑推进。

### 4. 顶部信息条「上岛」（灵动岛 / 胶囊形态）
- **来源**：用户群反馈（满月居于空、财税波哥）
- **现状**：[TopBarWindow.xaml.cs](../src/BingLan.App/Windows/TopBarWindow.xaml.cs) 内已有默认关闭的实验性胶囊骨架（`_enableExperimentalCapsule`），仅做过待办概要展开验证。
- **评估**：需补齐多模块摘要、动效、避让全屏与外观适配，排在核心稳定性与多屏之后。

### 5. 微信 / 钉钉等应用气泡消息弹窗
- **来源**：用户群反馈（财税波哥、家宝·Daily）
- **现状**：目前顶栏「消息提示」与 Dock 橙点 / 红数字胶囊仅响应 `HSHELL_FLASH`，不读取系统通知中心。
- **评估**：若做气泡弹窗，需评估 Windows `UserNotificationListener` 权限要求、隐私边界（[MVP-PRODUCT-DESIGN.md](MVP-PRODUCT-DESIGN.md) 明确不采集/不托管系统通知中心）以及微信/钉钉是否向系统投递 Toast 通知的兼容性。

### 6. Dock「始终显示且不占底栏空间」悬浮模式
- **来源**：用户群反馈（面朝大海cc）
- **现状**：[DockState.cs](../src/BingLan.Core/Models/DockState.cs) 提供「始终显示并保留底部空间（可勾选最大化时让出）」与「智能隐藏」两档。
- **评估**：若新增“始终悬浮且不预留工作区”，会与最大化窗口底边状态栏/输入区发生遮挡，需先明确与 `AGENTS.md` §6“全屏或最大化应用不能被 Dock 无意遮挡”的交互取舍后再决定是否作为显式可选进阶项引入。
