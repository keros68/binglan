# 顶端信息条真机验证

依据：[`DESKTOP-TOPBAR-DESIGN.md`](./DESKTOP-TOPBAR-DESIGN.md) §10 矩阵。
环境：Windows 11 Build 26200，双显示器（主屏 DISPLAY2 1920×1080 100%，副屏 DISPLAY1 1440×639），底部原生任务栏常驻；同屏运行用户在用的正式实例（隔离互不影响）。
方法：QA 模式（`--interactive-qa`，独立数据目录与实例门禁）启动本仓库构建，脚本核对显示器工作区与窗口；进程内行为由真实窗口的 UI 烟雾测试覆盖。

## 已验证（2026-10-10，本机自动化）

| 项 | 结果 |
| --- | --- |
| 预留模式：工作区变化 | 主屏工作区顶部间隙 0 → 31 像素预留（条高 32 像素，预留 = 条高 − 1，最大化窗口顶边贴入条底行，用户确认观感合适），底部任务栏 48 像素不变 |
| 预留模式：单显示器范围 | 副屏顶部间隙保持 0，不受主屏顶栏影响 |
| 窗口创建 | 预留与智能隐藏两种模式下均找到"顶端信息条"窗口（ToolWindow/NoActivate 扩展样式由 UI 烟雾测试断言） |
| 智能隐藏：不预留 | 主屏顶部间隙保持 0，窗口存在 |
| 进程强杀恢复 | taskkill /F 后工作区顶部间隙回到 0（Windows 随进程窗口销毁清理 AppBar） |
| 启动序列 | `startup.log` 依次记录"Dock 已应用 → 顶端信息条已应用 → 任务栏模式已应用"，顺序与设计一致 |
| 与正式实例共存 | QA 实例与用户正式实例并行运行，互不影响（独立门禁与数据目录） |
| 模块渲染与交互 | UI 烟雾测试在真实会话验证：模块渲染、音量读出真实值（WASAPI COM）、输入法读出真实输入法状态并断言圆角徽标、输入法名与悬停布局名、时钟/待办/天气/性能文本、天气 tooltip、点击路由、模块开关、UIA 名称与 Invoke 模式；天气为无按钮语义的展示元素 |
| 输入法中/英徽标与输入法名 | 真实输入验证（Build 26200，本机输入法 HKL=0x08040804，TSF 名"微信输入法"）：徽标与"前台布局 + imm32 转换模式"的独立重算一致；真实注入 Shift 切换中/英模式后 600 毫秒内徽标翻转且与模式位一致（无人操作会话完整通过；用户在场时注入会被真实输入抢占，属实验伪影）；输入法名与 TSF `ITfInputProcessorProfileMgr::GetActiveProfile` 独立直读一致，圆角徽标块与顶栏背景亮度差实测，悬停出现完整名玻璃 tooltip（像素差分）。转换模式经 `ImmGetDefaultIMEWnd` + `WM_IME_CONTROL/IMC_GETCONVERSIONMODE`（`SendMessageTimeout` 50 毫秒防挂起）读取；**打字高峰 IME 窗口忙会超时读不到模式，徽标沿用上帧值不闪回退**（实测发现）。TSF 名走 UI 线程（STA 要求）且仅在布局句柄变化时重读；徽标随 150 毫秒前台节拍即时刷新 |
| AppBar 预留扰动截图工具（用户报告修复） | 用户实测：顶栏预留模式下微信 Alt+A 截图界面 300 毫秒后收缩到另一块屏（遮罩从全虚拟桌面缩为副屏单屏），退出冰蓝则正常。根因：`ABN_POSCHANGED`（自动隐藏任务栏的显隐会持续广播）到达时顶栏每次都重发 `ABM_SETPOS`，而每次 `ABM_SETPOS` 都触发系统工作区重算并向全部窗口广播屏幕变化，微信收到后重排截图遮罩。修复=预留矩形与当前一致时直接跳过 `ABM_SETPOS`。用户真实触发三次现场监测验证：修复前收缩副屏、退出冰蓝正常、修复版与退出冰蓝行为一致（遮罩全程保持全虚拟桌面）。附注：微信截图结束时主窗瞬间拉伸跨屏（1442×850 → 约 2 倍尺寸并溢出虚拟桌面）在无冰蓝时同样发生，为微信在混合 DPI 双屏（主屏 100%/副屏 200%）下的自身缺陷，与本应用无关 |
| 系统表面跳转 | 真实合成输入端到端验证（Build 26200）：点击音量模块→托盘快速设置弹层弹出（托盘区像素差分）→再点复原（差分归零）；点击性能模块→任务管理器出现且“性能”导航处于选中态（UIA），随后关闭。该轮快速设置经 UIA 调用托盘图标；任务管理器导航在窗口重建期间逐次重读 |
| 天气悬停详情 | 真实悬停（合成输入）验证：停留约 0.5 秒后玻璃 tooltip 在条下方弹出（条下区域像素差分 111 万），离开后收起；WPF 自带 tooltip 在无激活窗口不打开，改为条自管的停留后弹出（UI 测试覆盖开合） |
| 日历信息栏 | 真实合成点击验证：点击时钟模块后日历浮层出现在顶栏下方（区域像素差分 700 万），再点收起；UI 测试覆盖今天日期、星期表头、开合切换。系统日历面板不再调用——见下 |
| 系统弹层可重定位性 | 实证（Build 26200）：该轮检查未找到可供迁移的独立面板窗口，未验证面板重定位；电量/网络/音量维持唤起系统快速设置，日历改为顶栏自建只读月历 |
| 待办信息栏 | UI 烟雾测试验证：点击待办模块弹出清单（标题/未完成/完成项），条目点击切换完成状态并联动同一状态对象；再点模块收起。跨进程/点外收起由条自管（StaysOpen=true + 150ms 轮询 + 打开时消费按键锁存 + 排除待办按钮防连按重开），已用真实合成输入（mouse_event）端到端验证：打开后 900ms 仍开、点空白条面收起、按钮重开与收起、条目点击切换完成态并经去抖保存落盘 |
| 天气刷新节奏 | 15 分钟成功间隔守卫（评审修复 M4） |

## 未验证（留人工或后续环境）

- 真全屏应用（无边框铺满）运行时顶栏退避与恢复：需真实全屏视频/游戏，不在自动化会话安全范围内。
- Win+D / 最小化所有窗口后顶栏保持可见：顶栏常驻置顶带（与任务栏/Dock 同层），按结构应保持，但未在本机实测（模拟全局输入会干扰用户会话）。
- Explorer 重启后的预留恢复：需重启用户会话的 Explorer，不在安全范围内；TaskbarCreated 恢复路径与 Dock 控制器逐段一致（评审核对）。
- 125%/150% 缩放：主屏当前 100%，未覆盖高缩放。
- 所选显示器断开后的回落与恢复：需拔插显示器。
- 消息提示的真实闪烁流（真实应用发闪烁请求、点击聚焦）：需交互场景；核心队列逻辑有核心烟雾测试。
- 点击深链打开设置中心并选中组件的端到端流转：组件级有测试，App 级流转未自动化。

## 托盘连续唤出与恢复验证（2026-10-20）

结论：**本机连续失败恢复和正常退出清理通过，正式入口继续保留在实验范围外**。兼容范围仍限于下述环境。

环境：Windows 11 25H2，Build 26200.9711，单显示器 2560×1440、125%，中文系统。实验使用独立个人配置，不修改正式用户配置；托盘唤出逻辑仅在 UI 测试项目的 `TrayOverflowExperiment` 中，不进入生产程序。

| 检查 | 本轮观察结果 |
| --- | --- |
| 实验中的并发去重 | 一个请求 `opened`、另一个 `busy`；随后重复请求为 `already-open`，面板保持可见 |
| 普通自动隐藏 | 连续 20 轮通过；每轮检查打开、重复请求不关闭、关闭及收回。交替使用原生按钮关闭和切换回验收窗口两种方式 |
| 自动隐藏及仅底部两角唤出 | 连续 20 轮通过；拦截细条已实际出现。补充并发用例到循环用例的衔接复验，再次完成 20 轮。循环前等待原生关闭动画结束。三组共 60 轮，任务栏状态始终为 1，关闭后矩形回到 `(0,1438)-(2560,1498)` |
| 保持面板与切换焦点 | 面板保持 5 秒后仍可见；切换到另一个真实 WPF 验收窗口后，任务栏收回，新窗口保留前台焦点 |
| 故障注入 | 发出通知区域聚焦请求后，故意跳过隐藏图标按钮调用。普通自动隐藏、两角模式各连续 20 次通过，共 40 次；每次均检查面板不可见、任务栏矩形收回及任务栏设置不变 |
| 面板打开时退出 | 两种模式均通过。退出前确认面板打开，清理后截图确认浮层消失且任务栏收回；销毁窗口后 300 ms 再检查 `overflow-visible=False`，原任务栏设置恢复为 0 |
| 唤出中退出 | 两角模式下，在发出通知区域聚焦请求后立即退出，请求返回 `cancelled`；清理检查和窗口销毁后的检查均为 `visible=False`，原任务栏设置恢复为 0。此用例覆盖调用原生按钮之前的取消 |
| 普通退出 | 未打开浮层、任务栏保持系统默认时，通过 Alt+F4 关闭验收窗口，清理完成且设置仍为 0 |
| 验收清理 | 退出后临时数据目录已清理，验收进程已结束，原任务栏设置恢复为 0 |

本轮截图位于本机 `artifacts/shell-surfaces/20261020-031959/`（普通模式）、`20261020-032143/`（两角模式）、`20261020-032553/`（衔接复验）。两组退出检查均包含 `overflow-exit` 和 `overflow-exit-cleaned` 前后截图。早期截图可能包含桌面工作内容，所有截图仅供本地检查，不对外上传。

失败基线中，连续故障注入第 3 次超过 3 秒未收回；仅恢复焦点后退出，浮层可见标志仍为 `True`。定位确认失败时的前台窗口为 Explorer 的 `Windows.UI.Composition.DesktopWindowContentBridge`，其根窗口是 `Shell_TrayWnd`。实验按根窗口归属识别任务栏及浮层内部焦点，其他应用保留焦点；退出通过同一个原生隐藏图标按钮关闭本次实验打开的浮层，等待完成后再销毁宿主窗口。不能以恢复焦点或 UIA 调用成功代替关闭检查。

恢复等待最多 500 ms，面板关闭检查每 150 ms 运行一次、仅在该面板会话中启用。退出清理取消待处理请求并等待最多 2 秒，原生按钮调用返回后最多等待 1 秒确认浮层关闭；失败时保留验收窗口供恢复或重试。UIA 提供程序阻塞、调用按钮后的取消和异常终止仍需专项验证。正式集成前需要可靠的 Explorer 关闭事件及更广泛兼容验证。
