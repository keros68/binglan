# Windows 任务栏适配真机验证

## 26300.9974 更换预览时的 Explorer 崩溃

2026-11-27 两次替换预览时，Windows 应用程序日志在 22:40 和 23:19 记录了相同的 Explorer 异常（`0xC000027B`）。两份转储中，冰蓝的任务栏组件正在注册 `AdviseVisualTreeChange`。Explorer 的贴靠布局线程同时在 `XamlDiagnostics::GiveRootsToCallback` 枚举现有根对象，转换对象失败后触发系统快速终止，尚未派发冰蓝的单根回调。

26300 系列仅在已验证的 26300.9711 上启用 XAML 透明。其他修订号或读取不到修订号时，选择透明将使用窗口模糊，保留用户选择。顶栏与 Dock 的材质由冰蓝单独控制。

在双屏桌面、个人任务栏设置为透明的条件下，使用完整预览连续替换三次，每次观察约 48 秒。Explorer 进程及主任务栏窗口句柄始终一致，应用程序日志和转储目录都没有新增 Explorer 崩溃记录。三次均使用窗口材质，Explorer 未加载冰蓝的 XAML 组件。最终预览的顶栏电量、音量、网络和托盘弹层均实际打开。

## 实现要点

- **透明**：Windows 11 Build 26200 与 26300.9711 使用自有 XAML 组件，只改变任务栏背景的透明度，保留原属性并在停止时恢复。其他 Windows 11 版本改用模糊并提示“此 Windows 版本暂用模糊代替透明”。Windows 10（Build 19041–21999）使用窗口材质 `ACCENT_ENABLE_TRANSPARENTGRADIENT`（渐变色 0），与模糊共用保活和检查点恢复（恢复时材质设回禁用），不加载 XAML 组件。远程会话、高对比度或检测到其他任务栏工具时保持默认；系统透明效果关闭时由宿主自动开启并在恢复时还原原值（用户开启期间手动关闭则让出）。结构、构建和恢复协议见 [任务栏 XAML 适配](TASKBAR-XAML.md)。
- **模糊**：保留系统窗口材质后端；实际效果随 Windows 版本变化，不将接口成功视为视觉成功。
- **自动隐藏**：通过文档化的 `SHAppBarMessage(ABM_SETSTATE)` 开启系统自动隐藏；原本已开启时不接管。用户自行关闭时尊重该选择。
- **恢复**：修改前记录恢复信息。透明背景在正常退出、宿主异常退出或心跳失效后由 Explorer 内组件恢复；自动隐藏和旧版窗口材质仍使用退出、下次启动和 `--restore-taskbar` 恢复。恢复未确认时保留检查点。

## 2026-10-03 透明效果实测

环境：Build 26200，浅色主题，Windows 透明效果开启，按用户安装的正式版本，TranslucentTB 已退出。在任务栏内距屏幕底边 12 px 处取样；x=300 处任务栏正上方的壁纸是深色岩石（`#6A767E`），x=600 处是水面。

| 任务栏状态 | x=300 | x=600 | 结论 |
| --- | --- | --- | --- |
| 系统默认 | `#DADADA` | `#DADADA` | 浅灰 |
| 冰蓝“透明”（`ACCENT_ENABLE_TRANSPARENTGRADIENT`，颜色 0） | `#D2F0F5` | `#D2F0F5` | 均匀浅蓝，两处颜色相同，不透出壁纸 |

## 「禁止鼠标触边唤出」冲突排查与真机验证清单（2026-11-22）

### 1. 源码级冲突分析与实际生效行为

1. **最大化窗口底边（已修复误暂停 + 明确边界）**
   - 原实现中 `WidgetCoordinator` 用 `FullScreenWatcher.IsFullScreenInFront` 暂停挡板，但该属性未排除最大化普通窗口；任务栏自动隐藏且 Dock 智能隐藏时，最大化窗口铺满整屏会误触发暂停，导致挡板失效。已改为绑定 `FullScreenWatcher.IsTrueFullScreenInFront`（`excludeMaximized: true`）：最大化普通窗口保持生效，仅真全屏应用撤下挡板。
   - 固有边界：不注入 Explorer 前提下，全宽 2 物理像素置顶细条会吞掉屏幕最底 2 物理像素的鼠标点击（150% 缩放约 1.3 DIP），仅在用户主动选择「禁止鼠标触边唤出」时生效；带 `WS_MAXIMIZE` 样式的无边框窗口化游戏也会被 `IsZoomed` 判为最大化窗口而不撤下挡板（见下表第 10 项）。
2. **Dock「只用屏幕底边」与「底边和把手」唤出（Z 序协调，无回路）**
   - Dock 底边唤出通过 `GetCursorPos` + `DockRevealRules.IsInRevealZone` 判定屏幕坐标，不依赖命中任务栏窗口，因此 2 px 挡板不会阻止 Dock 底边唤出；不能在 Dock 隐藏时挖空挡板，否则唤出 Dock 时原生任务栏会同时弹出。
   - Z 序调整：显示桌面时先抬挡板再抬 Dock；`TaskbarCornerReveal` 每次重排或置顶后触发 `Raised` 事件，由 `WidgetCoordinator` 调用 `_dock.EnsureAboveDesktop()` 保持可见 Dock 与把手位于挡板之上。
   - **防回环与 Z 序保障**：`IceBlueDockWindow.EnsureAboveDesktop()` 仅对本进程自己的 Dock HWND（`DockAppBarController.UpdateWindowLayer`：`SetWindowPos(..., SwpNoMove | SwpNoSize | SwpNoActivate)`）和把手 HWND（`DockHandleWindow.EnsureAboveDesktop`：`SetWindowPos(..., SwpNoMove | SwpNoSize | SwpNoActivate)`）重申 Z 序；`DockAppBarController.UpdateWindowLayer` 与 `TopBarAppBarController.UpdateWindowLayer` 在 `SetWindowPos` 期间置位 `_updatingLayer`，阻断同步回流的 `WM_WINDOWPOSCHANGED → SHAppBarMessage(ABM_WINDOWPOSCHANGED)`（此前常显预留空间模式下会触发 Explorer 把 `Shell_TrayWnd` 重新抬到挡板之上，导致三档选项无差别）；`TaskbarCornerReveal` 另通过 `EVENT_SYSTEM_FOREGROUND` 仅在检测到任务栏位于细条之上时复位，且内部保留 `_raising` 重入卫士。
3. **全屏切回与 Explorer 重启**
   - `TaskbarCornerReveal.SetSuspended(false)` 恢复后立即补一次 `Raise()`；`TaskbarAdapter` 收到 `TaskbarCreated` 后触发 `ExplorerRestarted`，立即重建挡板与新 Explorer PID 的 `WinEventHook`（不再等待 5 秒轮询）。

### 3. 2026-11-23 真机记录（Windows 11 Build 26300，3840×2160 单屏）

- 设为“禁止鼠标触边唤出”并运行冰蓝桌面：鼠标慢速、快速压到底边中间与左端，光标可到屏幕最底行，原生任务栏均未弹出；带标题栏、铺满显示器的窗口在前台时同样未弹出。
- 光标进入最底 2 行像素（`y ≥ 屏高 - 2`）即会触发弹出；停在 `屏高 - 3` 不触发。
- 曾评估用低级鼠标钩子把光标夹在 `屏高 - 3`：同样有效，但会让每次鼠标移动经过本程序，界面卡顿时影响全系统输入，且被系统摘除后需重装；因挡板已满足需求而未采用。
- 未覆盖：多显示器、混合 DPI、Explorer 重启后的挡板重建，仍按上表由用户核对。

### 4. 2026-11-24 回归验证（Windows 11 Build 26300.9974，3840×2160 单屏，Dock 始终显示并保留底部空间）

- 复现背景：正式版 `0.4.3` 在 Dock 设为“始终显示并保留屏幕底部空间”时，[DockAppBarController.cs](../src/BingLan.App/Dock/DockAppBarController.cs) 的 `UpdateWindowLayer` 回流触发 `ABM_WINDOWPOSCHANGED`，导致 Explorer 把 `Shell_TrayWnd` 压回 2 px 挡板上方，三档“鼠标触边唤出”选项无差别。
- 修复后在 `%LOCALAPPDATA%\BingLan-Preview` 预览版实测通过：常显预留空间 Dock + 任务栏自动隐藏下，三档“鼠标触边唤出”切换生效。
- 仍未覆盖：多显示器、混合 DPI、Explorer 重启与全屏切回后的长期回归。

## 原有窗口材质后端的限制

- 恢复时透明、模糊一律回到 Windows 系统默认外观。Windows 没有读取任务栏当前材质的接口，冰蓝桌面只在检测不到其他任务栏工具时接管，按“接管前就是系统默认”处理；如果名单之外的工具事先改过任务栏外观，退出后不会还原成那个外观。
- 安装、更新和卸载时按安装路径强制结束冰蓝桌面，最后约 350 ms 内尚未落盘的改动可能丢失；任务栏与桌面图标的恢复记录不受影响。
- 从托盘或组件菜单“退出”的恢复路径与“切回系统默认”共用同一段代码，本轮没有单独在真机上点击退出验证。
- 系统界面换回材质到重新设置之间可能有一瞬间的闪烁；兜底补设间隔为 2 秒。
- 应用请求注意（任务栏按钮闪烁）时，Windows 会让自动隐藏的任务栏保持显示，此时任务栏会盖住 Dock 下沿。
- 注销或关机时会按正常退出恢复自动隐藏；下次登录启动后重新应用。
- 未覆盖：多显示器（副任务栏）、100%/150% 缩放、远程桌面、卸载程序调用。
- Windows 10 的自动隐藏、模糊、透明尚未经真机验证。待验证：三种样式的视觉效果；开始菜单、通知中心开合和窗口最大化后样式是否保持；Explorer 重启后重新应用；切回默认与正常退出后恢复；强制结束后下次启动按检查点恢复；多显示器时副任务栏同样生效。

## 2026-11-28 双屏托盘兼容性实测

Windows 11 Build 26300，主屏 3840×2160、175%，副屏 2560×1440、150%。测试期间保留 Explorer 托管图标，预先启动独立的限时恢复程序。

- 修复预览中，从冰蓝面板点选「冰蓝桌面」，设置窗口取得前台。点选微信时，Windows 任务栏先短暂获得前台，随后切换到微信。采样期间两个 Dock 的位置与高度保持稳定。
- 在主副屏任务栏窗口上仅请求隐藏，副屏会再次可见。先禁止窗口输入，再对两个窗口施加隐藏后，冰蓝面板中单击微信仍能切换到微信。切换期间 546 次窗口可见性采样均为隐藏。另用专门的测试图标确认原应用可收到右键并打开菜单。
- 保存和恢复分别按窗口句柄核对。测试后两块任务栏均已恢复可见、可接收输入，系统自动隐藏已恢复，两屏底边各露出 2 像素。上述测试未覆盖 Explorer 重启、冰蓝异常退出及全部第三方托盘菜单。

### Clash Verge 2.5.10 默认左键
