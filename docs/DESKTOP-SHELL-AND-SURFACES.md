# 桌面表面、冰蓝 Dock 与原生任务栏设计决策

状态：已决策，作为后续实现和验收的主边界。  
范围：桌面组件呈现、统一设置、冰蓝 Dock、Windows 原生任务栏适配。

## 1. 结论

冰蓝桌面不再以一个通用“卡片底座”承载所有能力。桌面上的时间、天气、性能、待办、分组盒和 Dock 各自使用符合内容语义的表面；统一的只是视觉令牌、逐卡拖动与锁定规则、数据服务、持久化和 App 设置入口。

Windows 原生任务栏与冰蓝 Dock 是两个独立模块：

- **Windows 原生任务栏**仍由 Explorer 提供开始菜单、托盘、通知和任务栏按钮；冰蓝桌面只控制保持默认、透明/模糊、智能隐藏。
- **冰蓝 Dock**是应用启动与窗口切换表面，负责固定应用、运行状态、窗口分组、激活/最小化、排序和智能隐藏；它不是第二套 Windows 任务栏。
- **苹果式桌面**是“冰蓝 Dock 开启 + Windows 原生任务栏智能隐藏”的组合效果，不替换 Explorer，也不模拟系统托盘和开始菜单。

## 2. 桌面与 App 的职责边界

### 2.1 普通桌面状态

桌面只显示用户要看的内容和完成任务所需的直接动作：

- 时间、日期、天气结果和性能数值；
- Reminders 风格的待办标题、待办项、完成状态、新增和隐藏已完成；
- 分组盒标题、文件/应用入口，以及添加、排序、自动整理等内容动作；
- 冰蓝 Dock 的应用图标、运行状态和窗口切换。

普通状态不常驻显示：拖动手柄、关闭组件、城市设置、颜色值、圆角、数据源、刷新策略、实现说明或使用提示。用户单击选中卡片后，只临时显示进入冰蓝桌面 App 的设置按钮；便签另显示正文样式按钮。未锁定卡片可从标题或非交互空白区域直接拖动；复选框、文本输入、新增、删除等内容区域保持原本的单一行为。

### 2.2 逐卡移动与锁定

桌面不再依赖一个难以理解的全局“编辑布局”开关：

- 每张卡片默认可从标题或空白区域移动；
- 标题未编辑时属于拖动区域；双击标题或按 F2 进入编辑，Enter 提交，Esc 取消；
- 每张卡片在 App 中独立锁定，锁定只禁止移动，不禁用内容交互；
- 拖动卡片边缘或四角调整尺寸，也可在 App 的对应组件详情中输入精确值；
- 卡片设置入口只负责跳转到 App 中的对应详情，不在桌面展开平行控制台；
- 内容控件仍保持原本的单一行为，不把复选框、文本输入和删除操作当成拖动区域。

桌面仍保持低干扰内容态，不使用悬停来偷偷暴露常驻设置工具。

### 2.3 冰蓝桌面 App 设置

“桌面组件”页使用左侧组件列表和右侧详情，不使用难以浏览的下拉选择。以下内容只在 App 中配置：

- 组件显示、标题、文字颜色、背景材质、透明度、圆角、字号和信息密度；
- 问候称呼、12/24 小时制、天气城市和刷新状态；
- 待办/便签/分组盒的管理入口；
- Dock 的固定应用、位置、显示器、尺寸、放大和智能隐藏；
- Windows 原生任务栏模式及恢复状态；
- 隐私、性能、备份、导入和开机启动。

桌面组件右键菜单最多提供“在冰蓝桌面中设置”、删除组件和退出，不再承载一套平行设置页。

## 3. 表面类型

生产 UI 按语义选择表面，不再继承统一的标题栏布局：

| 表面 | 主要内容 | 普通状态外壳 |
| --- | --- | --- |
| 环境信息层 | 时间、日期、问候、天气、性能 | 无标题栏或低容器感 |
| Reminders 待办 | 标题、待办项、完成状态、新增 | 内容卡，可保留内容标题 |
| 便签 | 标题、正文 | 纸张/玻璃工作表面 |
| 分组盒 | 文件、文件夹、应用映射 | 容器表面和内容工具 |
| 冰蓝 Dock | 应用图标、运行与活动状态 | 独立悬浮条 |
| 顶端信息条 | 时间、待办概要、天气、性能、只读系统状态、消息提示 | 顶边满宽细条（高度固定 32 DIP） |

`WidgetWindowBase` 只负责 HWND、DPI、命中测试、位置恢复和材质令牌，不再决定所有表面的标题栏、按钮、行高和内容布局。

## 4. 三种桌面模式

| 模式 | 顶端信息条 | 冰蓝 Dock | Windows 原生任务栏 | 适用场景 |
| --- | --- | --- | --- | --- |
| Windows 原生 | 关闭 | 关闭 | 保持系统默认 | 最稳妥、最接近系统默认 |
| 冰蓝混合 | 关闭 | 开启 | 透明/模糊 | 同时保留原生按钮与 Dock |
| 苹果式 | 开启（时间/天气/性能卡关闭） | 开启 | 智能隐藏 | 以顶边信息条与居中 Dock 为主要入口 |

模式是对三个独立模块的编排，不允许把 Dock、任务栏和顶端信息条的设置存成互相覆盖的同一字段。用户仍可在高级设置中分别调整三个模块；切换模式只是写入一组安全默认值（苹果式同时把时间/天气/性能三张信息卡切为隐藏，避免同一份数据显示两次）。

## 5. 实施边界

### 5.1 DesktopHost

- 维护每张卡片的位置、尺寸、可见与锁定状态；未锁定时开放非交互区域拖动。
- 向各表面传播统一的命中与锁定规则，但不注入统一标题栏。
- 使用 DPI 无关坐标，处理显示器断开和工作区变化。

### 5.2 DockHost

- 复用隔离实验中已验证的窗口枚举、分组和激活逻辑。
- 视觉层使用独立的 `IceBlueDockWindow`，默认不占满整条屏幕。
- AppBar/工作区预留必须可选；最大化、全屏和第三方 AppBar 冲突时优先回退为覆盖或隐藏。
- 生产合并前完成按开发机实际硬件收缩的矩阵：本机显示器配置、Explorer 重启、最大化/全屏回避和日常应用清单实测；多显示器与混合 DPI 推迟到具备对应环境时补充。

### 5.3 TaskbarAdapter

- 单独保存进入冰蓝桌面前的任务栏状态。
- 应用模式失败时回退系统默认，不影响 DesktopHost 和 DockHost。
- Explorer 重启后只重放仍然有效且用户启用的策略。
- 退出、崩溃恢复和卸载都必须恢复；透明模式只允许通过 Windows XAML 诊断接口加载自有任务栏背景组件，不要求管理员权限。

## 6. 实施顺序与验收门

1. **表面纠偏**：普通态去除桌面配置文字；卡片默认可移动并可逐卡锁定，全部配置集中到“桌面组件”列表与详情。
   验收：待办、信息层和分组盒桌面只保留内容；空白区可拖动，锁定后不可拖，内容输入始终可用。
2. **Dock 兼容门**：保持隔离实验形态，按开发机实际硬件收缩——本机显示器配置、Explorer 重启、最大化/全屏回避和日常应用清单实测。
   验收：所有失败都能释放工作区并回退。状态：本机单屏 125% 通过，见 [`DOCK-QA.md`](./DOCK-QA.md)。
3. **冰蓝 Dock 视觉与逻辑分层**：兼容门通过后，把隔离 Dock 的诊断条迁移为正式的居中内容宽度表面，同时保持窗口跟踪可测试。
   验收：固定/运行/分组/切换可用；不模拟开始菜单和托盘。状态：已迁入正式应用，默认关闭，在设置中心“Dock”页开启。
4. **任务栏隔离实验**：实现默认、透明/模糊、智能隐藏和原状态恢复。  
   验收：退出、强制终止后恢复流程、Explorer 重启和不支持版本回退通过。状态：正式适配器已接入，本机结果见 [`TASKBAR-QA.md`](./TASKBAR-QA.md)。
5. **三模式编排进入设置 App**：只在 Dock 与 TaskbarAdapter 都通过各自兼容门后开放。  
   验收：模式切换不破坏原生开始菜单、托盘、通知和任务栏按钮。状态：已在“布局”页开放。

## 7. 当前阶段不做

- 不创建 macOS 任务栏或菜单栏替代品；顶端信息条只承载冰蓝自有的只读数据与状态，不读取应用菜单、不承载托盘/控制中心/通知中心，不是对它们的模拟。
- 不替换 Explorer、开始菜单、系统托盘、Alt+Tab 或 Shell。
- 不把任务栏适配代码放进任一桌面卡片、Dock 或顶端信息条视图模型。
- 不把未通过恢复验证的任务栏开关暴露为可点击的生产设置。
